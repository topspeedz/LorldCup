# blender-pipeline

Blender MCP는 **실행 중인 Blender 하나**를 Python으로 조종한다. 그래서 세 가지를 지킨다. 남의 작업을 덮지 않는다. 화면보다 수치를 먼저 본다. 웹 런타임이 읽을 수 있는 것만 결과로 친다.

## 1. 시작: 연결과 점유

1. `get_addon_status`로 연결, Blender 버전, 켜진 자산 라이브러리와 생성기를 확인한다. 연결되지 않으면 Blender를 직접 띄우지 않고 `ask`로 올린다. Blender와 애드온은 사용자가 켠다.
2. 점유 표시 `_workspace/graphicmodel/blender-lock.json`을 본다.
   - 있고 `task`가 내 Task가 아니면 Blender를 건드리지 않는다. `ask`로 올리고 턴을 끝낸다. 앞 Task가 끝났는지는 띄운 쪽이 안다.
   - 없으면 만든다: `{ "task": "<Task ID>", "dispatch": "<Dispatch ID>", "file": "<.blend 경로>", "started": "<시각>" }`.
3. 지금 열린 파일을 본다(`bpy.data.filepath`, `bpy.data.is_dirty`). 내 파일이 아닌데 저장되지 않은 변경이 있으면 덮지 않고 `ask`로 올린다. 없으면 내 `.blend`를 열거나 새로 만들어 저장한다.
4. 파일을 열거나 새로 만든 직후 `get_addon_status`를 다시 불러 연결이 살아 있는지 본다. 끊겼으면 `ask`로 올린다.

MCP 도구의 `user_prompt` 칸에는 spec의 `목표` 문장을 그대로 넣는다. 사람 이름, 이메일, 비밀 값을 넣지 않는다.

## 2. 작업 중 수칙

| 수칙 | 이유 |
| --- | --- |
| 작은 단계로 나눠 실행하고, 알아야 할 값은 `print`한다 | 긴 스크립트는 어디서 틀렸는지 알 수 없다 |
| 수치를 먼저 뽑고 화면은 그다음에 본다. 바운딩 박스, 변환, 축, 재질 슬롯, 토폴로지와 가중치(`get_scene_info`의 `topology`, `weights`)를 본 뒤 `look`으로 확인한다 | 화면 한 장은 축, 스케일, 로컬 변환, 숨은 오브젝트를 가린다 |
| `bpy.ops`보다 데이터 API(`bpy.data`, 속성 직접 수정)를 쓴다. ops가 꼭 필요하면 `bpy.context.temp_override`로 대상과 모드를 명시한다 | ops는 컨텍스트에 따라 조용히 실패한다 |
| 셰이더 노드는 이름이 아니라 `type`으로 찾는다(`n.type == "BSDF_PRINCIPLED"`). enum 값은 기억으로 쓰지 않고 읽는다(`bl_rna.properties[...].enum_items`) | 노드 이름은 언어 설정에 따라 바뀌고, enum은 버전에 따라 바뀐다 |
| 모르는 API는 `dir()`과 `bl_rna`로 먼저 확인한다 | Blender 버전에 따라 API가 다르다(예: 액션의 F-커브 접근 방식) |
| 재질 색은 셰이더 노드 입력에 넣는다 | `material.diffuse_color`는 뷰포트에만 보이고 GLB에 가지 않는다 |
| 변환 적용, 병합, 삭제, 이름 일괄 변경 전에 대상 목록을 `print`해 리포트에 남긴다. 숨은 헬퍼와 프록시는 용도를 확인하기 전에 지우지 않는다 | 되돌릴 수 있어야 하고, 지운 이유가 남아야 한다 |
| 위치, 회전, 스케일을 따로 검사한다. "전부 적용"을 습관으로 누르지 않는다 | 의도한 변환까지 지워지고, 스킨이 걸린 메시는 리그가 깨진다 |
| `look`은 빠른 확인이면 `max_size`를 줄이고(예: 512), 여러 각도는 `mode="angles"` 한 번으로 본다 | 이미지는 대화에 계속 남는다 |

## 3. 자산을 구하는 순서와 비용

1. 소유자의 자산(브리프나 spec이 가리킨 경로)을 먼저 쓴다.
2. 없으면 `search_assets`(Poly Haven, Sketchfab, Poly Pizza)로 찾는다. `previews`로 먼저 보고 가져온다.
3. 없으면 직접 만든다.

- 가져온 자산은 출처(라이브러리, id, 제작자)를 리포트의 `## 자산 출처`에 적는다. 기억으로 적은 이름은 "확인 안 됨"으로 표시한다.
- **`generate_3d`는 호출마다 비용이나 월 생성 횟수가 든다.** spec에 허용이 적혀 있을 때만 쓴다. 없으면 `ask`로 올린다. 물체 하나만 만든다(장면 전체, 바닥, 조립용 부품은 안 된다). 같은 물체가 여러 개 필요하면 다시 생성하지 않고 복제한다. 이미지는 절대 경로나 URL로 넘긴다.
- 가져오거나 생성한 모델은 크기와 방향이 제멋대로다. 보고된 바운딩 박스로 크기를 맞추고 바닥에 놓은 뒤 `look`으로 확인한다. 생성물은 출발점이다. 토폴로지, 예산, 텍스처에 구워진 조명을 확인하고 고친다.

## 4. 파일 배치와 이름 (출발값)

자산 연동 규약 `docs/live/web-metaverse-develop/asset-contract.md`가 있으면 그 문서가 정본이다. 없을 때만 아래를 쓰고, 리포트에 "규약 없음, 출발값 사용"이라고 적는다.

| 무엇 | 경로 |
| --- | --- |
| 원본과 참고 자료 | `art/<종류>/<이름>/` 아래 `<이름>.blend`, `ref/`(참고 이미지), `notes.md`(분석과 추정 메모) |
| 내보낸 모델 | `public/assets/<종류>/<이름>.glb` |
| 효과음 | `public/assets/audio/sfx/<이름>_<NN>.<확장자>` |
| 미리보기 이미지 | `_workspace/graphicmodel/<phase>/preview/<이름>_<각도>.png` |

- `<종류>`는 `props`, `environment`, `characters`, `vfx` 가운데 하나다.
- 파일 이름은 소문자와 하이픈만 쓴다. 오브젝트, 재질, 클립 이름에 공백과 `.001` 같은 접미사를 남기지 않는다.
- 코드가 이름으로 찾는 것(노드, 재질, 뼈, 클립)은 규약의 고정 문자열을 그대로 쓴다. 이름을 바꾸는 것은 규약을 바꾸는 것이다.
- 단위는 미터다(1 = 1 m). 실제 크기로 만든다. 바닥에 놓이는 것은 원점을 바닥 중심에, 회전하는 부품은 회전축에 둔다.
- 정면은 Blender에서 −Y를 바라보게 둔다. glTF로 가면 +Y가 위, +Z가 앞이 된다. 처음 한 번은 방향을 적은 시험 상자를 내보내 확인한다.

## 5. 내보내기

**glTF로 가는 것과 가지 않는 것.**

| 간다 | 가지 않는다 (바꿔야 간다) |
| --- | --- |
| 메시, UV, 정점 색 | 모디파이어 (적용하거나 내보내기 옵션으로 적용) |
| Principled BSDF 하나에 연결된 값과 이미지 텍스처: 베이스 컬러, 금속, 거칠기, 노멀, 이미시브, 알파 | 절차적 텍스처 노드와 노드 수식 (이미지로 베이크) |
| 뼈대와 스킨 가중치, 셰이프 키 | 컨스트레인트, IK, 드라이버 (키로 베이크) |
| 변환·뼈·셰이프 키 애니메이션 (액션이 클립이 되고 액션 이름이 클립 이름이 된다) | 파티클, 물리와 유체 시뮬레이션 (셰이프 키나 뼈 애니메이션으로 베이크하거나 플립북으로 렌더) |
| | Blender의 조명 세기, 뷰 변환, 월드 설정 (런타임이 다시 맞춘다) |

**내보내기 전.**

- 스케일은 1, 회전은 0으로 맞춘다. 스킨이 걸린 메시는 `blender-character`의 순서를 따른다.
- 빈 재질 슬롯, 쓰지 않는 UV 세트, 정점 색, 셰이프 키를 지운다. 면에 할당되지 않은 재질은 내보내지지 않는다.
- 뒤집힌 노멀, 겹친 정점, 넓이가 0인 면, 닫히지 않은 가장자리를 검사한다(`get_scene_info(fields=["topology"])`).

**내보내기.**

- 형식은 GLB 하나다(텍스처 포함).
- 내보내기 연산자의 옵션 이름은 Blender 버전마다 다르다. 기억으로 쓰지 않고 먼저 읽는다: `[p.identifier for p in bpy.ops.export_scene.gltf.get_rna_type().properties]`. 정할 것은 선택한 것만 내보내기, 모디파이어 적용, +Y 위, 애니메이션을 묶는 방식, 텍스처 형식이다.
- 압축(Draco, Meshopt, KTX2)과 텍스처 형식은 자산 연동 규약이 정한 것만 쓴다. 런타임에 디코더가 등록돼 있어야 열리기 때문이다. 규약이 없으면 압축 없이 내보내고 리포트에 "압축 미적용"이라고 적는다.
- 프로젝트에 없는 외부 도구(예: `gltf-transform`, KTX 변환기)는 spec이나 규약에 적혀 있을 때만 쓴다. 없으면 새 의존성이므로 `ask`로 올린다.

## 6. 자체 점검 (넘기기 전)

1. **수치.** spec의 예산을 옵션으로 넣어 돌리고 출력 전체를 리포트에 붙인다.

   ```sh
   node .claude/skills/blender-pipeline/scripts/glb-inspect.mjs <파일.glb> --names --max-tris <N> --max-draws <N> --max-texture-px <N>
   ```

   옵션은 `--max-tris`, `--max-draws`, `--max-materials`, `--max-textures`, `--max-texture-px`, `--max-texmem-mb`, `--max-joints`, `--max-kb`다. 예산을 넘으면 코드 1로 끝난다. `--names`는 노드와 재질 이름을, `--json`은 전체를 JSON으로 찍는다.
2. **다시 열기.** `.blend`를 저장한 뒤, 내보낸 GLB를 임시 컬렉션에 가져와 계층, 재질, 클립 이름과 길이, 크기, 방향이 원본과 같은지 본다. 본 뒤 임시 컬렉션을 지운다. 가져오기가 성공한 것만으로 런타임에서 열린다고 적지 않는다.
3. **눈.** `look(mode="angles")`로 앞, 옆, 위, 3/4를 본다. 미리보기 이미지는 bpy 렌더로 파일로 저장해(512~1024px) 리포트에 경로를 적는다. 고치기 전과 뒤는 같은 카메라와 조명으로 찍는다.
4. **기준을 옮기지 않는다.** 통과하려고 허용치를 넓히거나 측정 대상을 바꾸지 않는다. 예산을 넘으면 넘는다고 적고, 고칠 수 없으면 `ask`로 올린다.

## 7. 끝내기

- `.blend`를 저장한다. 점유 표시를 지운다. 지우는 것은 내 Task의 것뿐이다.
- 리포트는 `docs/harness/templates/report.md` 뼈대에 아래 절을 더한다. 뒤 Task(이펙트, 성능 점검, 웹 런타임)가 이 표를 읽는다.

```markdown
## 넘기는 것
| 파일 | 삼각형 | 드로 콜 | 재질 | 텍스처(수, 최대 변) | 뼈 | 클립(이름, 길이) | 압축 | 비고 |

## 자산 출처
| 자산 | 출처(라이브러리, id, 제작자) | 고친 것 |

## 추정한 것
| 부분 | 추정 내용 | 근거 |
```
