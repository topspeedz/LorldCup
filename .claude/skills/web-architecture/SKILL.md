# web-architecture

두 문서는 팀이 병렬로 일하기 위한 약속이다. 아키텍처 문서는 웹 팀 안의 경계를, 자산 연동 규약은 그래픽 팀과 웹 팀 사이의 경계를 정한다. 경계가 먼저 정해져야 양쪽이 서로를 기다리지 않는다.

| 문서 | 경로 | 누가 읽나 |
| --- | --- | --- |
| 아키텍처 | `docs/live/web-metaverse-develop/architecture.md` | 웹 개발자 둘, 리뷰와 QA |
| 자산 연동 규약 | `docs/live/web-metaverse-develop/asset-contract.md` | 그래픽 팀 전원, 3D 개발자, 성능 검증, QA |

이 Task가 고칠 수 있는 것은 두 문서와 `_workspace/web-metaverse-develop/`뿐이다. 코드는 고치지 않는다.

## 원칙

| 원칙 | 이유 |
| --- | --- |
| 구조는 복잡해진 만큼의 값을 해야 한다 | 패턴을 장식으로 쓰면 고칠 곳만 는다 |
| 좋은 방법이 아니라 주고받는 것을 적는다. 고른 것으로 무엇을 잃는지 쓴다 | 다시 논쟁하지 않게 된다 |
| 되돌리기 쉬운 결정을 먼저 고른다 | 초기에는 모르는 것이 많다 |
| 의존의 방향을 지킨다. 규칙(이동, 상태 전이)이 화면 도구나 통신 방식에 기대지 않는다 | 바꿀 수 있고, 렌더 없이 시험할 수 있다 |
| 경계마다 약속을 일하기 전에 정한다. 약속은 Task로만 바꾼다 | 구현 중에 한쪽이 몰래 바꾸면 다른 쪽이 깨진다 |
| 같은 수치는 한 곳에만 적는다 | 두 곳에 적으면 어긋난다. 예산과 이름의 정본은 연동 규약이다 |
| 새 의존성, 기술 결정의 변경, 외부에 쓰는 행위, 비용은 사용자 결정이다 | 문서로 정하지 않고 `## 결정 필요`에 올린다 |

## 절차

1. **입력.** 브리프의 `## 사용자 결정`, 설계서, 지금의 두 문서, 코드의 실제 구조(`package.json`, 폴더), 아트 디렉션 문서, 그래픽 팀 리포트의 `## 넘기는 것`.
2. **요구 모으기.** 기능 요구와, 기능이 아닌 요구(대상 기기, 한 화면의 최대 사용자 수, 성능, 보안)를 표로 모은다. 없는 것은 가정으로 적고 `## 결정 필요`에 올린다. 숫자를 지어내지 않는다.
3. **경계와 소유.** 모듈을 나누고, 상태마다 주인을 정하고, 3D와 UI 사이의 약속을 정한다.
4. **결정 기록.** 결정마다 맥락, 고른 것, 고르지 않은 것과 이유, 결과(잃는 것)를 쓴다.
5. **연동 규약.** 아래 뼈대로 쓴다. 항목마다 검사 방법을 붙인다. 검사할 수 없는 항목은 약속이 아니라 바람이다.
6. **대조.** 아트 디렉션 문서와 어긋나는 곳(스타일이 요구하는 것이 예산을 넘는가)을 찾아 `## 결정 필요`에 올린다.
7. **구조를 바꿀 때.** 바꾸기 전에 세 칸으로 평가한다.

   | 복잡도가 얼마나 느나 | 되돌리는 데 얼마나 드나 | 명령으로 검증할 수 있나 |
   | --- | --- | --- |

현재 상태만 담는다. 대체된 결정은 지운다. 경과는 git에 남는다.

## 아키텍처 문서의 뼈대

```markdown
# 아키텍처

- 읽는 시점: 웹 코드의 Task를 받았을 때, 웹 Task의 spec을 쓸 때
- 역할과 소유 범위: 웹 앱의 구조, 모듈 경계, 상태의 소유, 3D와 UI 사이의 약속
- 소유 에이전트: metaverse-develop-leader
- 마지막으로 갱신한 phase: <phase>

## 1. 한눈에
모듈과 의존의 방향. 폴더와 모듈의 대응.

## 2. 모듈 경계
| 모듈 | 맡는 것 | 맡지 않는 것 | 폴더 | 담당 에이전트 |

## 3. 상태의 소유
| 상태 | 주인 | 누가 읽나 | 얼마나 자주 바뀌나 |
프레임마다 바뀌는 값은 3D의 루프가 갖는다. 화면 요소가 보는 값은 공용 저장소에 드물게 쓴다.

## 4. 3D와 UI 사이의 약속
공용 약속 파일의 경로(하나). 저장소의 키와 행동, 이벤트 이름, 글자 입력 중의 키 처리, 캔버스 자리의 신호(멈춤, 해제).

## 5. 서버와의 통신
무엇으로 잇는가, 메시지의 모양, 갱신 빈도, 서버가 정하는 범위, 다시 잇기.

## 6. 렌더 설정
렌더러, 톤 매핑과 노출, 색 공간, 픽셀 비율 상한, 품질 단계, 측정용 통로.

## 7. 검증 명령
`AGENTS.md`의 `명령` 절에 올릴 명령과 무엇을 보증하는지.

## 8. 유효한 결정
| 결정 | 맥락 | 고르지 않은 것과 이유 | 잃는 것 |

## 결정 필요
| 정할 것 | 후보 | 추천 | 사용자 결정인가 |
```

## 자산 연동 규약의 뼈대

```markdown
# 자산 연동 규약

- 읽는 시점: 자산을 만들거나 내보낼 때, 자산을 불러오는 코드를 쓸 때, 자산을 검사할 때
- 역할과 소유 범위: 그래픽 팀의 자산이 웹 런타임에 들어오는 형식, 이름, 예산
- 소유 에이전트: metaverse-develop-leader
- 마지막으로 갱신한 phase: <phase>

## 1. 파일 위치와 이름
| 종류 | 경로 | 이름 규칙 |

## 2. 단위, 축, 원점
1 = 1 m. 위와 앞의 방향. 종류마다 원점의 자리.

## 3. 형식과 압축
GLB. 지오메트리 압축과 텍스처 형식(런타임에 디코더가 등록된 것만). 디코더 파일을 받는 곳.

## 4. 재질
금속·거칠기 모델. 묶는 채널. 색 공간. 텍스처 크기 상한. 쓰지 않는 재질 기능.

## 5. 노드 이름
코드가 이름으로 찾는 노드. 부착 자리의 이름. 충돌용 메시의 표기와 보이지 않게 하는 방법.

## 6. 뼈대와 클립
뼈 이름 목록. 기본 포즈. 클립 이름 목록. fps. 제자리인지 루트 이동인지. 반복 클립의 끝 프레임 처리.

## 7. 이펙트와 효과음
큐 표의 형식. 효과음 이벤트 이름 규칙. 효과음 파일의 형식.

## 8. 예산
| 종류 | 삼각형 | 드로 콜 | 재질 | 텍스처(수, 최대 변) | 뼈 | 파일 크기 |
장면 합계: 드로 콜, 보이는 삼각형, 텍스처 메모리. 한 화면의 최대 캐릭터 수.

## 9. 검사
| 항목 | 명령 | 통과 |

## 결정 필요
```

- 예산의 출발값은 `web3d-performance`의 `references/budgets.md`에서 가져온다. 캐릭터 한 명의 예산은 장면 예산을 한 화면의 최대 캐릭터 수로 나눠 구한다. 최대 캐릭터 수가 정해지지 않았으면 가정을 적고 올린다.
- 9절의 검사는 프로젝트에 있는 명령으로 쓴다. 수치와 이름은 `glb-inspect.mjs`로 검사할 수 있다.

  ```sh
  node .claude/skills/blender-pipeline/scripts/glb-inspect.mjs public/assets/characters/<이름>.glb --names --max-tris <N> --max-draws <N> --max-joints <N> --max-texture-px <N> --max-kb <N>
  ```

- 코드가 이름으로 찾는 것(노드, 재질, 뼈, 클립, 이벤트)은 목록으로 적는다. "적당한 이름"은 약속이 아니다.
- 압축을 정하면 런타임에 그 디코더를 등록하는 일이 따라온다. 둘을 같은 phase에 넣는다.
- 규약을 바꾸면 이미 만든 자산이 어긋난다. 바꿀 때는 영향을 받는 자산 목록을 리포트에 적는다.

## 흔한 실수

| 실수 | 결과 |
| --- | --- |
| 구현하면서 약속을 정함 | 3D와 UI가 서로 다른 이름을 쓴다 |
| 공용 약속 파일을 여러 Task가 동시에 고침 | 충돌한다. Task 하나만 편집 범위에 넣는다 |
| 예산을 규약과 아트 디렉션 양쪽에 적음 | 어긋난다 |
| 검사 방법이 없는 규약 항목 | 지켜졌는지 아무도 모른다 |
| 최적화 도구의 기본값을 그대로 씀 | 노드가 합쳐지고 이름이 사라져 코드가 찾지 못한다. 규약에 이름 보존을 적는다 |
| 통신 방식이나 라이브러리를 문서로 확정 | 새 의존성과 기술 결정은 사용자 결정이다 |

## 완료 기준에 쓸 수 있는 검사

- 유효한 결정 표의 줄마다 네 칸이 채워져 있다.
- 공용 약속 파일의 경로가 문서에 하나로 적혀 있다.
- 연동 규약 9절의 줄마다 명령과 통과 기준이 있다.
- 예산 표의 종류마다 빈 칸이 없다. 빈 칸은 `## 결정 필요`에 대응하는 줄이 있다.
- 두 문서에 날짜 붙은 경과와 대체된 결정이 없다.
