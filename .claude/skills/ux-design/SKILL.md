# ux-design

만들기 전에 정한다. 이 서비스의 사용자 불만은 거의 모두 "있는데 못 찾는다"였다: 앉으면 Full Mode 버튼이 사라지고 Alt나 Esc를 눌러야 나타난다(`web/ui/full-mode.js`의 `body.walking` 숨김), 커서가 사라진다, 로딩 화면이 없다, 어느 좌석에 앉을 수 있는지 모른다. 이 스킬은 그런 일을 구현 뒤에 찾는 대신 명세 단계에서 막는다. 결함 표와 판정은 쓰지 않는다. 산출물은 개발자가 그대로 만들 수 있는 명세와 확인 표다.

## 두 가지 일

| 배정 | 하는 일 | 언제 | 고칠 수 있는 것 |
| --- | --- | --- | --- |
| `UX 명세` | 요구사항 명세, 사용자 흐름, 상태별 조작 명세, 수락 기준 제안 | 화면이나 조작에 닿는 phase의 계획 전 | `docs/live/product/ux/`, `_workspace/product/` |
| `UX 동행` | 개발자와 상태별 확인 표대로 기능을 걸어 보고, 어긋난 줄을 개발자에게 넘긴다 | 개발 Task의 `worker_done` 전 | `_workspace/product/`의 자기 리포트뿐 |

## UX 명세

### 1. 요구사항 명세

요청, 백로그 항목, 브리프의 사용자 결정을 읽고 아래 표로 정리한다. 모든 요구를 빠짐없이 뽑고, 요구의 강도("반드시", "꼭" 대 "있으면 좋다")를 그대로 옮긴다. 소유자가 말하지 않은 숨은 요구(예: "Full Mode를 쓰고 싶다"는 "앉아서도 찾을 수 있어야 한다"를 품는다)는 근거와 함께 따로 적고 `결정 필요`로 올린다.

| ID | 구분 | 요구 | 강도 | 측정 방법 | 근거(원문이나 항목) |
| --- | --- | --- | --- | --- | --- |
| UX-R01 | 기능 | 앉은 상태에서 Full Mode에 들어갈 수 있다 | 반드시 | 앉은 직후 첫 화면 그림에 버튼이나 키 안내가 보인다 | BL-#### |

- 구분: 기능, 비기능(성능, 접근성, 모바일), 제약(정적 앱, 정책, 기존 동작과의 호환).
- 측정 방법이 없는 요구는 요구가 아니다. "빠르게"가 아니라 "클릭 뒤 한 프레임 안에 반응이 보인다"처럼 쓴다. 수치는 출처가 있을 때만 쓰고, 없으면 "출발값"이라고 표시한다.
- 과한 요구는 대안과 함께 적는다. 정적 앱(`web/`)과 지금 구조로 비싸지는 요구는 `결정 필요`로 올린다.

### 2. 사용자 흐름

기능마다 진입점에서 목표까지와 되돌아가는 길을 화살표로 쓴다. 각 단계에 "사용자가 무엇을 보고 무엇을 하는가"와 "무엇이 그것을 알려 주는가"(화면 요소, 키 안내, 소리, 3D 안의 표시)를 적는다.

```text
[입장] → [로딩 커버: 진행 표시] → [첫 화면: 조작 안내] → [좌석에 다가감: 앉을 수 있음 표시] → [E로 앉기]
   → [앉은 화면: 영상, Full Mode 버튼, 일어서기 안내] → [Full Mode] → [닫기(Esc) → 앉은 화면으로]
```

- 모든 흐름에 나가는 길이 있다. 나가는 길이 키 하나뿐이면 그 키가 화면에 적혀 있어야 한다.
- 행동마다 즉시 보이는 반응이 있다(누름, 진행, 완료, 실패). 반응이 없는 행동은 사용자가 되풀이한다.
- 처음 온 사람의 흐름을 따로 쓴다: 첫 조작(걷기)을 첫 30초 안에 알려 주고, 첫 성공은 실패할 수 없게 한다(출처: agency-agents game-designer의 온보딩 점검표, 출발값). 글로 가르치기보다 공간과 표시로 알게 한다.

### 3. 상태별 조작 명세

이 서비스의 상태는 아래와 같다. 기능마다 이 표를 채운다. 새 상태가 생기면 행을 더한다.

| 상태 | 무엇이 보이는가 | 무엇으로 조작하는가(마우스, 키, 터치) | 다른 상태에서 이 조작을 찾는 길 | 커서와 포인터 잠금 |
| --- | --- | --- | --- | --- |
| 첫 방문(설명 없음) | | | | |
| 로딩 중·실패 | | | | |
| 걷기(포인터 잠금) | | | | 잠김. 풀리는 키 |
| 앉기 | | | | |
| Full Mode | | | | |
| 작은 창·모바일(터치) | | | | 잠금 없음 |

- **숨은 조작 금지.** 한 상태에서 사라지는 조작은 "찾는 길" 칸을 채운다. 키를 눌러야 나타나는 버튼은 그 키가 화면에 적혀 있어야 찾을 수 있다. 칸을 채울 수 없으면 그 상태에서도 보이게 바꾼다.
- **포인터 잠금은 커서를 빼앗는다.** 잠긴 동안 화면 버튼은 눌리지 않는다. 잠금 중에 쓸 조작은 키로 주고 키 안내를 보이게 하고, 잠금을 푸는 키(Esc)와 다시 잠그는 방법을 적는다. 잠금이 풀린 순간 커서가 보이는지 적는다.
- **입력마다 대안.** 마우스 키보드, 터치, 키보드만. 한 입력에만 있는 조작은 다른 입력의 대안을 적는다(출처: agency-agents xr-interface-architect, 여러 입력과 접근성 대안).
- **보이는 상태.** 지금 어느 상태인지(앉음, 걷기, Full Mode) 사용자가 화면에서 알 수 있어야 한다(Nielsen 휴리스틱 1: 시스템 상태의 가시성).
- **공간 안의 표시.** 앉을 수 있는 좌석처럼 3D 안의 대상은 다가가면 보이는 표시와 키 안내를 둔다. 길을 미니맵이나 글에만 맡기지 않는다(출처: agency-agents level-designer, 빛·색·형태로 주의를 끈다).

### 4. 수락 기준 제안

UI 항목에는 기본으로 아래를 제안한다. `product-manager`가 항목에 옮긴다.

- 숨은 조작 없음: 처음 온 사람이 설명 없이, 표의 모든 상태에서 이 기능을 찾는다. 확인은 상태별 확인 표(아래)의 모든 줄이 그림 한 장이나 조작 한 번으로 맞는 것이다.
- 기능마다 나가는 길과 반응이 화면에 있다.

### 5. 상태별 확인 표

명세 끝에 둔다. 개발 Task spec의 완료 기준과 동행이 이 표를 그대로 쓴다. 결함 표가 아니다. 줄마다 기대만 적는다.

| # | 상태 | 하는 일 | 기대(그림이나 조작으로 확인) |
| --- | --- | --- | --- |
| W1 | 앉기 | 좌석에 앉은 직후 아무 키도 누르지 않는다 | Full Mode 버튼이나 그 키 안내(F)가 화면에 보인다 |

### 6. 문자열

버튼과 안내 문구는 행동과 대상을 말한다("확인"이 아니라 "Full Mode 닫기"). 같은 것은 어디서나 같은 이름으로 부른다. 키 안내는 키와 결과를 함께 쓴다("Esc 커서 풀기"). 아이콘만 있는 버튼은 보조 기술용 이름이 행동을 말한다(출처: voltagent ux-microcopy-reviewer, WCAG 2.2 2.4.4·3.3.2).

### 명세 문서의 뼈대

`docs/live/product/ux/<기능>.md`. 머리(읽는 시점, 역할과 소유 범위, 소유 에이전트, 마지막으로 갱신한 phase)는 `docs/harness/templates/live-doc.md`를 따른다. 현재 상태만 담는다.

```markdown
# <기능> UX 명세
## 1. 요구사항 명세 (표)
## 2. 사용자 흐름
## 3. 상태별 조작 명세 (표)
## 4. 수락 기준 제안
## 5. 상태별 확인 표
## 6. 문자열
## 결정 필요
```

## UX 동행

개발 Task가 구현을 마치고 `worker_done`을 내기 전에 한다. 목적은 판정이 아니라 개발자가 고칠 것을 그 자리에서 받는 것이다.

1. 개발자가 `send --to dispatch:<ux-designer의 id>`로 준비됐다고 알리면, 명세의 상태별 확인 표를 위에서부터 걷는다. 앱을 띄우고 상태마다 그림을 남긴다(`_workspace/product/<phase>/walk/`).
2. 줄마다 "맞음" 또는 "어긋남: 본 것"을 적는다. 심각도와 승인 판정은 붙이지 않는다.
3. 어긋난 줄을 개발자에게 바로 보낸다. 개발자가 고치고 다시 알리면 그 줄만 다시 걷는다. 주고받기는 기능 하나에 2회까지이고, 넘으면 코디네이터에게 `ask`로 올린다.
4. 명세가 틀렸다고 드러나면(지금 구조로 만들 수 없음) 명세의 그 줄을 고치고 리포트에 이유를 적는다. 흐름 자체를 바꿔야 하면 `ask`로 올린다.
5. 리포트 `NN_ux-designer_walk-<기능>_v<N>.md`에 걸어 본 표와 그림 경로를 남긴다.

동행할 UX 디자이너가 떠 있지 않으면 개발자가 같은 표를 스스로 걷고 자기 리포트에 남긴다. 표가 통로다.

## 하지 않는 것

- 모양(색, 글꼴, 크기, 아이콘, 토큰): `ui-design`.
- 백로그 항목 쓰기: `backlog-management`. 이 스킬은 제안만 넘긴다.
- 결함 표, 심각도, 판정: `qa-verification`, `change-review`.
- 코드: `web-feature`, `web3d-runtime`.
