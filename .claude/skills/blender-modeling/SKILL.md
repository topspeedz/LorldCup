# blender-modeling

형태는 참조에 있는 사실에서 나온다. 사실이 모자란 곳은 추정으로 채우되, 추정은 추정이라고 적는다. 그리고 웹 런타임과 같은 조건의 화면에서 맞아야 맞은 것이다.

Blender를 다루는 수칙, 파일 배치, 내보내기, 자체 점검은 `blender-pipeline`이 정본이다. 여기에 옮겨 적지 않는다.

## 절차

1. **시작.** `blender-pipeline` 1절(연결과 점유).
2. **대상 고정.** spec에서 아래를 표로 옮긴다. 빈 칸이 있으면 `ask`로 받는다.

   | 항목 | 값 |
   | --- | --- |
   | 용도 | 가까이 보는 주인공 자산 / 일반 / 배경 |
   | 보는 거리와 화면에서의 크기 | |
   | 대상 기기 | 데스크톱 / 모바일 |
   | 예산 | 삼각형, 재질 수, 텍스처 크기, 파일 크기 |
   | 필요한 재질 기능 | 알파(오려 내기 / 반투명), 이미시브, 유리 |
   | 움직이는 부분 | 없음 / 있음(피벗 위치) |

   아트 디렉션 문서 `docs/live/graphicmodel/art-direction.md`의 형태 언어, 색, 재질, 조명 규칙을 읽는다.
3. **자산 먼저 찾기.** `blender-pipeline` 3절. 있는 자산을 고쳐 쓰는 것이 처음부터 만드는 것보다 낫다.
4. **참조 분석.** [references/reference-analysis.md](references/reference-analysis.md)대로 `art/<종류>/<이름>/notes.md`에 쓴다: 자료 등급, 카메라(시점, 초점거리), 기준 치수, 부품 목록, 정체성을 정하는 디테일, 사실과 추정의 구분.
5. **카메라 맞추기와 블록아웃.** 참조 시점의 카메라를 만들고, 미터 단위 실제 크기로 큰 덩어리만 놓는다. 참조와 같은 카메라로 실루엣과 주요 경계선을 비교한다. **형태 결정은 여기서 잠근다.** 회색 덩어리에서 읽히지 않는 형태는 디테일로 고쳐지지 않는다.
6. **형태.** 모디파이어로 되돌릴 수 있게 진행한다(Mirror, Bevel, Array, Solidify).
   - 모디파이어는 순서가 결과를 바꾼다(대개 Bevel 다음 Mirror, Mirror 다음 Subdivision). 스케일이 축마다 다르면 Mirror와 Bevel 앞에서 스케일을 적용한다.
   - 실루엣을 바꾸는 것은 지오메트리로 만든다. 노멀 맵은 실루엣을 바꾸지 못한다.
   - 반복 부품은 메시 데이터를 공유한다. 그중 하나만 고칠 때는 먼저 데이터를 복제한다.
   - 사람이 지나다니거나 닿는 지오메트리(바닥, 계단, 문 폭)와 꾸밈 지오메트리를 구분해 이름이나 컬렉션으로 표시한다. 꾸미다가 동선을 깨지 않기 위해서다.
7. **디테일과 UV.** 삼각형은 실루엣과 가까이 보이는 곳에 쓴다. 평평한 면의 분할은 걷어 낸다. 날카로운 모서리 자리에서 UV를 나눈다. 텍셀 밀도를 고르게 한다.
8. **재질과 조명.** [references/materials-lighting.md](references/materials-lighting.md). Principled BSDF 하나에 glTF가 읽는 입력만 연결하고, 절차적 노드는 이미지로 베이크한다. 환경 조명 아래에서 보고, 런타임과 같은 계열의 톤 매핑으로 확인한다.
9. **검토 패스.** 0°, 90°, 180°, 270° 턴테이블과 참조 시점 비교를 한 묶음으로 본다.
   - 평면이 아닌 형태는 두 각도 이상에서 맞아야 한다.
   - 실루엣이 맞는 것만으로 통과시키지 않는다. 안쪽 디테일을 지운 모델도 실루엣은 똑같이 맞는다. 4단계의 정체성 디테일 목록을 하나씩 대조한다.
   - **수정 예산은 한 패스에 3번, 전체 6번이다.** 넘으면 멈추고 남은 차이를 리포트에 적는다. 같은 결함이 되풀이되거나 고칠수록 오락가락하면 더 일찍 멈춘다.
   - 패스마다 판단 한 줄을 `notes.md`에 남긴다: 계속 / 분석을 고침 / 제작을 고침 / 자료를 더 요청 / 중단.
10. **내보내기와 자체 점검.** `blender-pipeline` 5절과 6절.
11. **끝내기.** `blender-pipeline` 7절. 리포트에 런타임으로 넘길 메모를 더한다: 맵 목록과 색 공간, 환경 맵이 필요한지, 압축과 디코더, 피벗 위치, 조명 메모, glTF 표준 재질로 안 되는 표현의 요청.

## 기준 (출발값)

예산의 정본은 spec과 자산 연동 규약이다. 둘 다 없으면 `web3d-performance`의 `references/budgets.md`를 쓰고 리포트에 "출발값 사용"이라고 적는다.

| 항목 | 기준 |
| --- | --- |
| 단위와 크기 | 미터, 실제 크기. 바운딩 박스가 참조 치수와 허용 오차 안 |
| 변환 | 스케일 1(허용 0.0001), 원점은 spec대로, 바닥에 놓이는 것은 최저점이 0 |
| 이름 | 공백과 `.NNN` 접미사 없음, 빈 재질 슬롯 0 |
| 텍스처 크기 | 배경 512, 일반 1024, 가까이 보는 주인공 자산 2048. 4096은 쓰지 않는다 |
| 접지 | 바닥을 1~2 cm 넘게 파고들거나 뜨면 눈에 보인다 |

## 흔한 실수

| 증상 | 원인 |
| --- | --- |
| 한 각도에서는 맞는데 돌리면 틀리다 | 한 카메라 각도를 형태가 맞다는 증거로 썼다 |
| 색이 바래거나 너무 어둡다 | 색 공간이 뒤바뀌었다(색 맵은 sRGB, 나머지는 Non-Color) |
| 요철이 뒤집혀 보인다 | 노멀 맵 규약이 다르다(OpenGL, Y+를 쓴다) |
| 전부 플라스틱처럼 보인다 | 금속 값이 0이거나 환경 맵 없이 봤다 |
| 무늬 있는 표면이 가짜 같다 | 사진의 무늬를 절차적 재질로 흉내 냈다. 조명을 걷어 낸 참조를 투영한다 |
| 내보낸 GLB에 색이 없다 | 뷰포트 색만 바꿨다. 색은 셰이더 노드 입력에 넣는다 |
| 내보내니 형태가 다르다 | 모디파이어를 적용하지 않았다 |
| "지금은 상자, 나중에 제대로" | 임시 형태는 끝내 교체되지 않는다. 실제 물체는 처음부터 실제 형태로 만든다 |

## 완료 기준에 쓸 수 있는 검사

- `glb-inspect.mjs`에 spec 예산을 넣어 코드 0.
- bpy 출력: 모든 메시의 스케일 1, 이름에 공백과 `.NNN` 없음, 빈 재질 슬롯 0.
- 바운딩 박스 치수(m)와 원점 위치가 spec과 일치.
- 참조와 같은 시점의 이미지와 턴테이블 4장이 미리보기 폴더에 있다.
- `notes.md`에 추정 표가 있고, 리포트의 `## 추정한 것`과 같다.
