# 재질, 셰이더, 조명과 분위기

> 읽는 시점: `blender-modeling` 8단계. 캐릭터와 이펙트의 재질을 잡을 때도 같은 기준을 쓴다.

웹 런타임의 재질은 glTF의 금속·거칠기 모델이다. Blender에서 노드로 무엇을 만들든, Principled BSDF 하나에 이미지와 값으로 들어간 것만 넘어간다.

## 1. 채널마다 지킬 것

| 채널 | 기준 | 이유 |
| --- | --- | --- |
| 베이스 컬러 | 빛과 그림자를 넣지 않는다. 금속이 아닌 재질은 sRGB 약 50~240(가장 어두워도 약 30). 순수한 검정과 흰색을 쓰지 않는다 | 빛은 런타임이 계산한다. 구워 넣으면 조명이 바뀔 때 틀려진다 |
| 금속 | 0 또는 1. 회색은 녹이나 벗겨진 칠의 경계에만 | 넓은 회색 영역은 현실에 없는 재질이다 |
| 거칠기 | 한 값으로 칠하지 않는다. 닳은 곳, 먼지, 손자국으로 변화를 준다 | 고른 거칠기가 가짜처럼 보이는 가장 빠른 길이다 |
| 노멀 | OpenGL 규약(Y+). 평평한 곳은 (128, 128, 255). PNG로 저장 | 규약이 다르면 요철이 뒤집힌다. 손실 압축은 노멀을 깬다 |
| 이미시브 | 색과 세기를 함께 정한다 | 기본값이 검정이라 세기만 올리면 빛나지 않는다 |
| 알파 | 오려 내기는 `MASK`(기준 0.5). 반투명 `BLEND`는 부드러운 가장자리가 정말 보일 때만 | 반투명은 정렬 문제와 그리기 비용이 따른다 |
| 유리 | 불투명도가 아니라 투과(transmission)로 만든다. 모바일 대상이면 쓰지 않는다 | 불투명도로 만든 유리는 반사와 굴절이 틀린다. 투과는 그리기 비용이 크다 |

**거칠기 범위 (0~255).**

| 표면 | 값 |
| --- | --- |
| 거울 | 0~20 |
| 연마한 금속 | 20~50 |
| 광택 플라스틱 | 30~70 |
| 칠한 면 | 50~100 |
| 가공하지 않은 나무 | 150~200 |
| 콘크리트, 천 | 200~255 |

**금속의 반사색 (sRGB).** 알루미늄 245, 246, 246 / 철 약 197, 199, 200 / 금 약 255, 227, 157 / 구리 약 250, 209, 194.

## 2. 색 공간과 파일

| 맵 | 색 공간 | 형식 |
| --- | --- | --- |
| 베이스 컬러, 이미시브 | sRGB | 알파가 없으면 JPEG(품질 70~85), 있으면 PNG |
| 노멀, 금속, 거칠기, AO | Non-Color | PNG |

- 금속, 거칠기, AO는 한 장에 묶는다: R = AO, G = 거칠기, B = 금속.
- AO는 Principled BSDF에 입력이 없다. glTF 내보내기 애드온이 주는 출력 노드 그룹(`glTF Material Output`, 구버전 이름 `glTF Settings`)의 Occlusion에 연결해야 내보내진다. 이름은 버전에 따라 다르니 확인하고 쓴다.
- UV 섬 바깥으로 색을 충분히 번지게 한다(패딩). 모자라면 이음새에 선이 생긴다.
- 크기는 2의 거듭제곱으로 한다.
- JPEG로 바꾸면 내려받는 크기만 줄어든다. 그래픽 메모리는 그대로다.

**텍스처 한 장의 그래픽 메모리 (밉맵 포함, 압축 없음).** 512는 약 1.3 MB, 1024는 약 5.3 MB, 2048은 약 21 MB, 4096은 약 85 MB.

## 3. 넘어가지 않는 것을 넘기는 법

**베이크.** 절차적 텍스처, 노드 수식, 여러 셰이더의 혼합은 이미지로 구워야 넘어간다.

1. 대상 메시에 UV가 있고 겹치지 않는지 본다.
2. 맵마다 이미지 텍스처 노드를 만들어 활성으로 두고 Cycles로 굽는다.
3. 베이스 컬러를 구울 때는 직접광과 간접광을 끄고 색만 굽는다.
4. 구운 이미지를 Principled BSDF에 다시 연결하고, 원래 노드는 `.blend`에 남겨 둔다(다시 구울 수 있게).

**반복되는 노드 묶음.** 노드 그룹으로 만들고, 밖으로 내놓는 값에는 범위와 설명을 단다. 같은 묶음을 재질마다 복사하지 않는다.

**glTF 표준 재질로 안 되는 표현.** 가장자리 빛, 녹아 사라지는 효과, 흐르는 물결, 만화풍 음영 같은 것은 Blender 노드로 만들어도 넘어가지 않는다. 리포트에 **셰이더 요청**으로 적어 넘긴다. 구현은 `metaverse-3d-developer`가 한다.

```markdown
## 셰이더 요청
| 대상 | 원하는 화면(이미지 경로) | 조정할 값과 범위 | Blender에서 쓴 노드 구성 | 모바일에서의 대체안 |
```

## 4. 조명과 분위기

**승인하는 화면.** Blender의 기본 뷰포트가 아니라 환경 조명(HDRI) 아래에서, 런타임과 같은 계열의 톤 매핑으로 본다. 런타임의 톤 매핑과 노출은 아키텍처 문서가 정한다. 정해지지 않았으면 리포트에 "런타임 톤 매핑 미정, Blender 기본으로 확인"이라고 적는다.

| 항목 | 기준 |
| --- | --- |
| 환경 맵 해상도 | 일반과 모바일 1K, 가까이 보는 장면 2K |
| 노출 | 1.0이 중립. 0.5~0.8은 어두운 분위기. 1.5를 넘으면 밝은 곳이 날아간다 |
| 색온도 | 낮 4000~5000 K, 밤 2700~3000 K |
| 배색 | 바탕 60, 보조 30, 강조 10 |

**분위기를 넘기는 법.** Blender의 조명 세기와 월드 설정은 넘어가지 않는다. 런타임 조명은 개발 쪽이 다시 맞추므로 **조명 메모**를 넘긴다.

```markdown
## 조명 메모
| 빛 | 방향 | 색온도 | 상대 세기 | 그림자 | 역할(주광 / 보조광 / 윤곽광) |

분위기 키워드: <세 개 안팎>
환경 맵: <파일이나 출처>, 노출 <값>
```

**런타임의 한도를 알고 설계한다.**

- 실시간 조명은 데스크톱 3~5개, 모바일 1~2개다. 그림자를 드리우는 것은 데스크톱 2~3개, 모바일 0~1개다.
- 움직이지 않는 환경은 빛과 AO를 텍스처로 구워 실시간 조명 수를 줄인다.
- 시선을 끌 곳은 조명 수를 늘리지 않고 명도 대비와 색 대비로 만든다.

## 5. 흔한 실수

| 증상 | 원인 |
| --- | --- |
| 금속이 거칠어 보이거나 반대로 보인다 | 묶은 맵의 G와 B가 뒤바뀌었다 |
| 노멀이 깍두기처럼 깨진다 | 데이터 맵을 JPEG나 손실 압축으로 저장했다 |
| 디테일이 사라졌다 | 구운 노멀이 아니라 빈 노멀 채널을 내보냈다 |
| 모바일에서 탭이 죽는다 | 4096 텍스처, 또는 텍스처 수가 많다 |
| Blender에서는 좋았는데 웹에서 밋밋하다 | Blender 화면만 보고 승인했다 |
| 밝은 곳이 하얗게 잘린다 | 선형 톤 매핑에 밝은 환경 맵을 썼다 |
