# blender-character

캐릭터는 한 컨셉 안에서 변주한다. 고정된 것은 건드리지 않고, 허용된 축에서만 개성을 낸다. 그리고 메시와 뼈대가 있다고 리그가 된 것이 아니다. 합격 포즈와 수치로 증명한다.

Blender를 다루는 수칙, 파일 배치, 내보내기, 자체 점검은 `blender-pipeline`이 정본이다.

## 절차

1. **시작.** `blender-pipeline` 1절.
2. **캐릭터 계약.** 만들기 전에 아래를 한 표로 모은다. 빈 칸은 `ask`로 받는다.

   | 항목 | 어디서 읽나 |
   | --- | --- |
   | 공통 비례, 형태 언어, 팔레트 범위, 모션 성격 | 아트 디렉션 문서 `docs/live/graphicmodel/art-direction.md` |
   | 뼈 이름과 계층, 클립 이름 목록, fps, 제자리인지 루트 이동인지 | 자산 연동 규약 `docs/live/web-metaverse-develop/asset-contract.md` |
   | 삼각형, 재질, 텍스처, 뼈 수 예산 | spec과 규약 |
   | 납품 범위 | 정적 모델 / 리그 포함 / 클립 포함. spec에 없으면 묻는다 |
   | 합격 포즈 | 중립, 주요 관절의 극한 굽힘, 뻗기, 비틀기, 이동과 접지, 필요한 표정 |

3. **캐릭터 시트.** `art/characters/<이름>/sheet.md`에 쓴다(아래 양식). 다른 워커가 같은 캐릭터를 다시 만들 수 있을 만큼 적는다.
4. **공통 바탕에서 변주.** 공통 뼈대와 비례에서 시작한다. 공통 바탕이 아직 없으면 이 Task가 그것을 만든다는 사실을 리포트에 적는다. 단순한 전신을 먼저 끝내고 부위를 다듬는다.
5. **실루엣 테스트.** 이미 있는 캐릭터들과 나란히 놓고 단색 실루엣, 흑백, 작게 줄인 렌더를 만든다. 셋 모두에서 누구인지 구분돼야 한다. 웹 3D에서 캐릭터는 멀리, 작게 보이는 일이 많다.
6. **모델링.** 형태를 아직 고칠 수 있을 때 굽힘, 뻗기, 비틀기를 시험한다. 옷이나 장신구를 바꾸면 다시 시험한다. 손은 손바닥, 손등, 옆에서, 신발은 위와 옆에서 본 뒤에 디테일을 넣는다.
7. **리깅과 스키닝.** [references/rig-and-skin.md](references/rig-and-skin.md).
8. **애니메이션.** [references/animation.md](references/animation.md). 키 포즈 → 예비 동작, 접촉, 후속 동작 → 타이밍에 차이 주기 → 루프 이음매 → 큐 프레임 기록.
9. **동작 상태 점검.** 화면으로 판정하지 않는다. 처음, 중간, 접촉, 공중, 극단 프레임을 뽑아 수치로 본다(아래 기준 표).
10. **베이크와 내보내기.** 컨스트레인트, IK, 드라이버는 넘어가지 않으므로 키로 굽는다. 액션 하나가 클립 하나이고 액션 이름이 클립 이름이다. 그다음 `blender-pipeline` 5절.
11. **자체 점검.** `blender-pipeline` 6절에 더해, 합격 포즈 전부를 앞, 옆, 뒤, 변형되는 곳 근접으로 렌더해 직접 열어 본다.
12. **끝내기.** `blender-pipeline` 7절. 리포트에 아래 두 표를 더한다. 이펙트 담당과 웹 개발자가 이 표로 일한다.

```markdown
## 클립
| 클립 이름 | 프레임 범위 | fps | 루프 | 제자리 / 루트 이동 | 기준 이동 속도(m/s) | 큐 프레임(발 디딤, 접촉, 정점) |

## 소켓과 모프
| 이름 | 종류(뼈 / 빈 오브젝트 / 셰이프 키) | 용도 |
```

## 캐릭터 시트 양식

```markdown
# <이름>

## 고정값 (바꾸지 않는다)
| 항목 | 값 |
| --- | --- |
| 머리 색과 길이, 눈, 체형, 특이점, 기본 의상 | |

## 실루엣을 구분하는 요소
체형 / 머리 모양 / 버릇 자세 / 늘 지니는 소품 / 의상 윤곽 가운데 이 캐릭터가 쓰는 것

## 성격과 동작 기둥
성격 키워드 세 개 / 걷는 리듬 / 버릇 동작 / 하지 않는 동작

## 표정
| 감정 | 눈 | 눈썹 | 입 | 크기(성격에 따라) |

## 변주가 허용되는 범위
의상 변형, 색 조합, 소품
```

- 개성은 외형보다 움직임의 크기와 방식에서 나온다. 같은 기쁨도 활발한 캐릭터는 크게, 차분한 캐릭터는 작게, 소심한 캐릭터는 숨기듯 표현한다.
- 얼굴 구조, 나이, 체형을 실제로 다르게 만든다. 얼굴 하나에 색만 바꾼 캐릭터를 늘리지 않는다.

## 기준

예산의 정본은 spec과 자산 연동 규약이다. 없으면 `web3d-performance`의 `references/budgets.md`를 쓰고 "출발값 사용"이라고 적는다.

| 항목 | 기준 |
| --- | --- |
| 뼈 이름 | 규약의 목록과 차이 0 |
| 가중치 | 가중치가 없는 정점 0. 정점 하나에 영향을 주는 뼈 4개 이하 |
| 변환 | 오브젝트 스케일 1, 회전 0. 뼈는 스케일하지 않는다 |
| 지면 관통 | 2 cm 이하 |
| 스케일 변화 | 클립 안에서 5% 이하. 넘으면 리그나 상속 문제다 |
| 루트 방향 | 프레임 사이 30° 이하(의도한 급회전 제외) |
| 발 미끄러짐 | 디딤 구간 동안 발의 월드 위치 변화가 눈에 띄지 않는다. 수치를 리포트에 적는다 |
| 루프 | 첫 프레임과 끝 프레임의 뼈 회전 차이 0(또는 spec의 허용치) |
| 합격 포즈 | 부피가 꺼지지 않고, 관절이 접히며 무너지지 않고, 옷이 뚫리지 않는다 |

## 흔한 실수

| 실수 | 결과 |
| --- | --- |
| 한 각도의 화면으로 포즈가 맞다고 판정 | 축, 스케일, 접지 문제가 가려진다 |
| 포즈를 맞추려고 신체 비례를 고침 | 원인은 대개 축이나 가져오기 설정이다 |
| 스킨이 걸린 메시에 변환을 전부 적용 | 리그가 깨진다 |
| 나쁜 바인드 포즈를 가중치로 고치려 함 | 고쳐지지 않는다. 바인드 전에 변환을 정리한다 |
| 캐릭터마다 다른 뼈 이름이나 비례 | 클립을 함께 쓸 수 없다 |
| 캐릭터마다 다른 모션 성격 | 컨셉이 깨진다 |
| 리그 수치는 통과했는데 옷과 관절 면이 틀림 | 수치만 보고 합격 포즈 렌더를 열어 보지 않았다 |
| GLB를 다시 가져오는 데 성공했으니 끝났다고 봄 | 런타임에서의 재생은 다른 문제다. 클립 표를 넘겨 웹 쪽 확인을 받는다 |
| 통과하려고 표식을 옮기거나 허용치를 넓힘 | 결함이 그대로 넘어간다 |

## 완료 기준에 쓸 수 있는 검사

- bpy 출력: 뼈 이름 집합이 규약과 일치(차집합 0), 가중치 없는 정점 0, 스케일 1.
- `glb-inspect.mjs --names --max-tris <N> --max-joints <N>`이 코드 0이고, 찍힌 애니메이션 이름이 규약의 클립 목록과 같다.
- 클립마다 샘플 프레임 표(지면 관통, 스케일 변화, 루트 방향, 발 미끄러짐)가 리포트에 있다.
- 실루엣 나란히 보기 이미지와 합격 포즈 렌더가 미리보기 폴더에 있다.
- `sheet.md`가 있고 고정값 표에 빈 칸이 없다.
