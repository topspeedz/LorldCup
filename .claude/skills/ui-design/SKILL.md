# ui-design

UX 명세는 "무엇이 언제 보이고 무엇을 누르는가"를 정했다. 이 스킬은 그것이 "어떻게 보이는가"를 정한다. 개발자가 값을 짐작하지 않게, 모든 값은 토큰 표에서 나오고 모든 화면은 상태마다 시안이 있다. 코드는 쓰지 않는다.

## 순서

1. **읽기.** UX 명세 `docs/live/product/ux/<기능>.md`, 아트 디렉션 `docs/live/graphicmodel/art-direction.md`, 기존 토큰 표 `docs/live/graphicmodel/ui/tokens.md`, 지금 화면의 캡처. UX 명세가 없으면 멈추고 `ask`로 올린다.
2. **토큰.** 필요한 값을 토큰 표에서 찾고, 없으면 아트 디렉션의 팔레트와 톤에서 만들어 표에 더한다(아래 「토큰 표」).
3. **화면 명세.** 상태마다 화면 요소의 자리, 크기, 위계, 겹침 순서를 쓴다(아래 「화면 명세」).
4. **컴포넌트의 상태.** 요소마다 기본, 올림, 누름, 초점, 비활성, 진행 중의 모양을 토큰으로 적는다.
5. **시안.** 상태마다 실제 3D 장면 캡처 위에 겹친 그림을 만든다. 단색 바탕 시안은 넘기지 않는다. 영상이 재생되는 장면, 밝은 곳과 어두운 곳을 모두 본다.
6. **찾는 길 확인.** UX 명세의 "다른 상태에서 이 조작을 찾는 길" 칸이 시안에서 보이는지 상태마다 본다. 보이지 않으면 모양을 고친다. 모양으로 풀 수 없으면 `ux-designer`에게 넘길 줄로 적는다.
7. **리포트.** `## 넘기는 것`에 화면 명세, 토큰 표, 시안 경로를 표로 적는다. 개발자는 이 표를 읽는다.

## 게임 HUD의 원칙

- **3D와 영상이 주인공이다.** 상시 요소는 화면 가장자리와 모서리에 모으고, 영상 화면과 화면 가운데(조준과 시선이 머무는 곳)를 비운다. 영상 위에 겹치는 요소는 언제 사라지는지 명세에 적는다.
- **위계는 셋 안팎.** 지금 할 일(주된 조작) > 상태(앉음, 걷기, Full Mode) > 보조(설정, 도움말). 강조색은 주된 조작 하나에만 쓴다.
- **숨기지 않고 줄인다.** 걷기 중에도 조작을 지우지 않고 작게, 흐리게, 키 안내로 남긴다. 키 안내는 키 모양(키캡)과 결과를 함께 보인다("F Full Mode").
- **어디서나 읽힌다.** 3D 장면의 밝기는 계속 바뀐다. 글자 뒤에 반투명 판이나 그림자를 두고, 밝은 곳과 어두운 곳의 캡처 둘 다에서 읽히는지 본다.
- **3D 안의 표시는 세계의 것.** 앉을 수 있는 좌석의 표시처럼 3D 안에 뜨는 것은 아트 디렉션의 효과 색과 밝기 위계를 따른다. 세부는 `graphic-effect-vfx-designer`와 맞춘다.
- **움직임은 상태를 알린다.** 나타남, 사라짐, 누름의 반응은 짧게 한다. 시간은 토큰으로 정하고, 움직임을 줄이는 설정(`prefers-reduced-motion`)에서는 움직이지 않는 대안을 적는다.

## 접근성의 하한

출처가 있는 수치만 쓴다.

| 항목 | 하한 | 출처 |
| --- | --- | --- |
| 본문 글자 대비 | 4.5:1 (큰 글자 3:1) | WCAG 2.2 1.4.3 |
| 버튼 테두리, 아이콘, 초점 표시의 대비 | 3:1 | WCAG 2.2 1.4.11 |
| 누르는 대상의 크기 | 24×24 CSS px 이상 | WCAG 2.2 2.5.8 |
| 색만으로 알리지 않음 | 모양이나 글자를 함께 | WCAG 2.2 1.4.1 |

- 대비는 3D 장면 캡처 위 실제 바탕에서 잰다.
- 모바일의 안전 영역과 엄지가 닿는 아래쪽을 처음부터 고려한다.

## 토큰 표

`docs/live/graphicmodel/ui/tokens.md`. 머리는 `docs/harness/templates/live-doc.md`를 따른다. 화면 명세와 시안의 모든 값은 이 표의 이름으로만 부른다.

| 토큰 | 값 | 쓰는 곳 | 근원 |
| --- | --- | --- | --- |
| `color-accent` | `#…` | 주된 조작 하나 | 아트 디렉션 5절 강조색 |
| `space-2` | 8px | 요소 사이 | 간격 단계 |
| `motion-fast` | …ms | 누름 반응 | 출발값 |

- 묶음: 색(바탕, 판, 글자, 강조, 상태), 글꼴과 크기 단계, 간격 단계, 모서리, 그림자와 판의 투명도, 움직임 시간과 커브, 겹침 순서(z).
- 값의 근원 칸을 비우지 않는다. 아트 디렉션에서 왔는지, 접근성 하한에서 왔는지, 출발값인지 적는다.
- 아트 디렉션에 없는 색이나 톤이 필요하면 만들지 않고 `graphic-leader`에게 `결정 필요`로 올린다.

## 화면 명세

`docs/live/graphicmodel/ui/<기능>.md`.

```markdown
# <기능> 화면 명세
- 입력: UX 명세 docs/live/product/ux/<기능>.md

## 상태별 배치
| 상태 | 요소 | 자리(기준 모서리와 여백 토큰) | 크기 | 위계 | 겹침(z) | 보임 조건 |

## 컴포넌트
| 요소 | 기본 | 올림 | 누름 | 초점 | 비활성 | 진행 중 |

## 작은 창·모바일
바뀌는 자리와 크기만.

## 시안
| 상태 | 그림 경로 | 장면(밝음/어두움/영상 재생) |

## 결정 필요
```

## 하지 않는 것

- 흐름, 상태, 조작의 결정: `ux-design`. 바꿔야 하면 넘긴다.
- 세계의 스타일과 팔레트 자체: `art-direction`.
- CSS와 코드: `web-feature`.
- 결함 표와 판정: `art-direction`의 아트 리뷰, `qa-verification`.

## 출처

- 토큰, 컴포넌트 상태, 넘김 명세, 접근성 기본: agency-agents `design-ui-designer`, `design-ux-architect`, voltagent `ui-designer`.
- 게임 HUD와 공간 UI: agency-agents `xr-interface-architect`(HUD와 떠 있는 메뉴, 편안한 배치), `game-designer`(피드백 체계), `level-designer`(빛·색·형태로 주의 끌기), voltagent `game-developer`.
- 문구와 접근성 수치: voltagent `ux-microcopy-reviewer`, WCAG 2.2.
