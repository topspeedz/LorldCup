# vfx-design

효과는 장식이 아니라 전달이다. 사용자가 무엇을 알아야 하는지 한 문장으로 말할 수 없으면 파티클부터 만들지 않는다. 그리고 효과와 소리에는 화면 위의 원인이 있어야 한다. 원인 없는 효과는 잡음이다.

이 역할이 만드는 것은 넷이다.

| 산출물 | 자리 | 누가 쓰나 |
| --- | --- | --- |
| 연출 명세와 큐 표 | `art/vfx/<이름>/spec.md`, `cues.json` | `metaverse-3d-developer`가 이대로 재생 코드를 짠다 |
| 효과 자산 | `public/assets/vfx/<이름>/` (GLB, 텍스처) | 런타임 |
| 효과음 | `public/assets/audio/sfx/` | 런타임 |
| 리포트 | spec의 `보고` 줄 | 팀장, 성능 검증 담당 |

웹에서 효과를 재생하는 코드(셰이더, 파티클 방출, 오디오 재생)는 이 역할이 쓰지 않는다. 명세로 넘긴다.

## 절차

1. **입력 확인.** 상호작용 명세(누가, 무엇을 해서, 무슨 결과가 나는가), 효과가 붙을 캐릭터 클립의 표(이름, fps, 큐 프레임, 소켓 이름. `graphic-character-designer`의 리포트에 있다), 대상 기기. 클립 표가 없으면 `ask`로 받는다. 큐를 짐작으로 놓지 않는다.
2. **목적.** "이 효과로 사용자가 무엇을 알게 되는가"를 한 문장으로 쓴다. 감정 목표 하나를 고른다. 모션 성격과 색 위계는 아트 디렉션 문서를 따른다.
3. **연출 명세.** [references/timing-and-cues.md](references/timing-and-cues.md)의 양식으로 `spec.md`를 쓴다. 예고, 타격, 여운의 단계와 층을 나누고, 값은 조정할 수 있는 이름 붙은 값으로 적는다.
4. **큐 표.** 캐릭터 클립의 접촉 프레임과 정점 프레임에서 `cues.json`을 만든다. 손으로 어림한 시각을 적지 않고 클립 표의 프레임에서 계산한다.
5. **예산 먼저.** 효과마다 파티클 수, 겹치는 반투명 층, 텍스처 크기, 드로 콜을 정한다. 출발값은 `web3d-performance`의 `references/budgets.md`다. 만든 뒤에 맞추지 않는다.
6. **Blender 제작.** `blender-pipeline` 1절로 시작한다. glTF로 가는 것만 Blender에서 만든다.
   - 간다: 효과 메시(고리, 파편, 궤적 띠, 빛기둥), 변환과 셰이프 키 애니메이션, 텍스처(마스크, 노이즈, 그라디언트, 플립북).
   - 가지 않는다: 파티클 시스템, 시뮬레이션, 셰이더 노드. 시뮬레이션은 셰이프 키나 뼈 애니메이션으로 굽거나, 프레임을 렌더해 플립북 한 장으로 묶는다.
   - 클립 이름과 프레임 범위를 큐 표와 맞춘다.
7. **웹 구현 사양.** glTF로 가지 않는 표현(파티클 방출, 녹아 사라짐, 가장자리 빛, UV 흐름, 빛 번짐)은 `spec.md`의 `## 구현 사양`에 적는다. 재질 구성, 조정 값과 범위, 섞는 방식, 쓰는 텍스처, 기준 프레임의 이미지.
8. **효과음.** [references/sound.md](references/sound.md).
9. **동기 점검.** 큐마다 앞 2프레임, 큐 프레임, 뒤 2프레임을 렌더해 변화가 큐 프레임에 보이는지 확인한다. 효과음이 시작되는 시각과 대조한다.
10. **최악의 경우.** 같은 효과가 동시에 최대로 터질 때의 파티클, 층, 드로 콜, 소리 수를 계산해 리포트에 적는다. 실측은 `graphic-performance-verifier`가 한다. 재지 않은 프레임 수를 주장하지 않는다.
11. **내보내기와 끝내기.** `blender-pipeline` 5~7절. 리포트에 아래를 더한다.

```markdown
## 효과
| 효과 | 트리거 | 붙는 클립과 소켓 | 명세 | 자산 | 효과음 이벤트 | 예산(파티클, 층, 드로 콜) |

## 효과음
| 이벤트 이름 | 파일(변형 수) | 길이 | 음량 | 2D / 3D | 우선순위 | 다시 틀기까지 최소 간격 |
```

## Blender에서 웹으로 옮기기

| Blender에서 | 웹에서 | 넘기는 방법 |
| --- | --- | --- |
| 변환, 뼈, 셰이프 키 애니메이션 | 클립으로 재생 | GLB |
| 파티클 시스템 | 인스턴스 메시나 점 파티클로 다시 구현 | 구현 사양(방출 수, 수명, 속도, 크기 곡선, 색 곡선) |
| 연기, 불, 액체 시뮬레이션 | 플립북 | 프레임을 N×M 한 장으로 묶은 텍스처와 재생 fps |
| 셰이더 노드로 만든 표현 | 런타임 셰이더로 다시 구현 | 구현 사양과 기준 프레임 이미지 |
| 빛나는 재질 | 이미시브 값이 1보다 커야 빛 번짐에 걸린다 | GLB의 이미시브와 명세의 세기 값 |

## 흔한 실수

| 실수 | 결과 |
| --- | --- |
| 효과음을 동작이 멈춘 프레임에 맞춤 | 접촉보다 늦게 들린다. 접촉 프레임에 맞춘다 |
| 큐 시각을 손으로 어림 | 실제 프레임과 어긋난다 |
| 클립의 타이밍이 바뀌었는데 큐를 그대로 둠 | 전부 어긋난다. 큐 표와 소리를 다시 만든다 |
| 모든 요소가 튕기고, 모든 동작에 소리 | 무엇이 중요한지 사라진다 |
| 더해서 섞는 반투명 파티클을 겹겹이 | 모바일에서 화면 채우기 비용이 폭증한다. 오려 내기를 먼저 쓴다 |
| 예산을 만든 뒤에 확인 | 다시 만든다 |
| 데스크톱 화면만 보고 승인 | 모바일에서 무너진다 |
| 같은 소리 한 개를 반복 | 기계처럼 들린다. 변형을 3~5개 둔다 |
| 효과가 캐릭터 얼굴이나 UI를 가림 | 피드백이 방해가 된다 |

## 완료 기준에 쓸 수 있는 검사

- `spec.md`와 `cues.json`이 있고, 모든 큐에 화면의 원인이 적혀 있다. 소리가 붙은 큐는 효과음 표에 같은 이벤트 이름이 있다.
- 큐마다 앞 2프레임, 큐, 뒤 2프레임 이미지가 미리보기 폴더에 있다.
- `glb-inspect.mjs`에 효과 예산을 넣어 코드 0이고, 찍힌 애니메이션 이름과 길이가 큐 표와 같다.
- 효과음 파일이 0바이트가 아니고, 길이가 명세와 같고, 이벤트마다 변형이 3개 이상이다.
- 품질 단계(높음, 보통, 낮음)와 동작 줄이기 대체안이 명세에 있다.
