# 효과의 설계, 타이밍, 큐

> 읽는 시점: `vfx-design` 3단계(연출 명세), 4단계(큐 표), 7단계(웹 구현 사양), 9단계(동기 점검).

## 1. 세 단계

| 단계 | 하는 일 | 형태와 색 |
| --- | --- | --- |
| 예고 | 곧 일어날 일을 알린다 | 작고, 어둡고, 한곳으로 모인다 |
| 타격 | 일이 일어난 순간 | 가장 밝고, 가장 크고, 가장 짧다 |
| 여운 | 일어났음을 남긴다 | 흩어지고, 채도와 밝기가 내려가고, 천천히 사라진다 |

- 한 순간에 주인공인 층은 하나다. 보조 층은 둘까지 둔다. 셋을 넘으면 시선이 흩어진다.
- 파티클을 늘리기 전에 대비, 방향, 타이밍, 크기로 해결한다.
- 가장 센 박자를 사건의 프레임과 소리가 시작되는 순간에 맞춘다.
- 효과의 크기는 원인의 크기에 맞춘다. 작은 일에 큰 효과는 결함이다.
- 캐릭터의 얼굴과 UI를 가리지 않는다. 효과의 중심은 사건이 일어난 자리(소켓)에 둔다.
- 다른 사용자의 효과도 같은 화면에 겹친다. 멀리서, 작게, 여럿이 겹쳐 보일 때도 읽히는 실루엣으로 만든다.

## 2. 시간

| 항목 | 값 |
| --- | --- |
| 즉각 반응(눌림, 선택) | 80~180 ms |
| 성공 표시(튀어나옴 + 작은 터짐) | 300~400 ms |
| 실패 표시(흔들림) | 300~400 ms, 2~3번, 넘쳤다 돌아오지 않는다 |
| 나타남과 사라짐 | 나타남이 사라짐보다 30~50% 길다. 나타남은 감속, 사라짐은 가속 |
| 차례로 나타나는 여러 개 | 간격 50~100 ms, 합쳐서 500 ms 미만 |
| 예비 동작 | 반대쪽으로 거리의 2~4%, 100~170 ms. 자주 쓰지 않는다 |
| 넘쳤다 돌아옴 | 실제로 닿았을 때만, 1~7% |
| 타격의 강조 | 빠르게 올라 지수적으로 줄어드는 한 번의 펄스. 좌우로 흔들리는 사인 곡선을 쓰지 않는다 |
| 타격 순간의 크기 | 착지 +2.5~3%, 작은 점 +18~30%, 닿을 때 가로 +8% / 세로 −10% |

- 커브와 스프링은 이름 붙인 몇 가지만 쓴다(효과 하나에 세 가지 안팎). 즉석 곡선은 스타일을 무너뜨린다.
- 닿는 것은 닿는 프레임에 아직 움직이고 있어야 한다. 감속하며 닿으면 소리를 둘 프레임이 없다.

## 3. 소리와 화면 맞추기

| 규칙 | 값 |
| --- | --- |
| 못 느끼는 어긋남 | 30 ms 미만 |
| 고장으로 느끼는 어긋남 | 100 ms 초과 |
| 소리가 화면보다 먼저 들린다고 느끼는 선 | 약 45 ms. 넘으면 소리가 아니라 화면을 옮긴다 |
| 화면 변화의 시작 | 큐보다 한 프레임 앞 |
| 펄스의 정점 | 소리가 시작된 뒤 약 30 ms |
| 예고의 소리 | 화면보다 먼저 시작해도 된다 |
| 타격의 소리 | 접촉 프레임 |
| 두 타격 사이 | 50~130 ms로 붙으면 뭉개진다. 하나로 합치거나 벌린다 |

큐를 놓는 자리:

| 사건 | 큐 프레임 |
| --- | --- |
| 착지, 타격, 맞닿음 | 접촉 프레임 (멈춘 프레임이 아니다) |
| 나타남 | 절반쯤 나타난 프레임 |
| 휙 지나감 | 가장 빠른 프레임 |
| 차오름 | 끝 |

## 4. 큐 표 `cues.json`

```json
{
  "effect": "high-five",
  "clip": "HighFive",
  "fps": 30,
  "cues": [
    { "id": "windup",  "frame": 6,  "phase": "예고", "visual": "glow-gather", "sound": null,        "weight": 0.3 },
    { "id": "contact", "frame": 18, "phase": "타격", "visual": "ring-burst",  "sound": "sfx.clap",  "weight": 1.0 },
    { "id": "settle",  "frame": 24, "phase": "여운", "visual": "spark-fade",  "sound": null,        "weight": 0.5 }
  ]
}
```

- `clip`과 `frame`은 캐릭터 담당의 클립 표에서 가져온다. 클립에 붙지 않는 효과는 `clip`을 `null`로 두고 `frame`을 효과 시작 기준으로 센다.
- `visual`은 명세의 층 이름, `sound`는 효과음 표의 이벤트 이름이다. 코드에 파일 경로를 적지 않고 이벤트 이름으로 부르게 한다.
- `weight`는 0~1의 크기다. 화면의 크기와 소리의 음량이 같은 값을 따른다.
- 클립의 타이밍이 바뀌면 이 파일을 다시 만든다.

## 5. 연출 명세 `spec.md` 양식

```markdown
# <효과 이름>

사용자가 알게 되는 것: <한 문장>
감정 목표: <하나>
트리거: <무슨 사건>
붙는 곳: <클립 이름, 소켓 이름>
길이: <ms>

## 층
| 층 | 단계 | 주인공 / 보조 | 형태 | 색과 밝기 | 시작(큐 기준 ms) | 길이(ms) | 커브 |

## 조정 값
| 이름 | 범위 | 기본값 | 무엇이 바뀌나 |

## 동시에 일어날 때
같은 효과의 동시 상한: <N>. 넘으면: <가장 오래된 것을 끝낸다 / 합친다 / 건너뛴다>
끝낼 때: <남은 것을 어떻게 치우나. 여러 번 불려도 안전하게>

## 품질 단계
| 단계 | 파티클 | 텍스처 애니메이션 | 빛 번짐 | 그 밖 |
| 높음 | | | | |
| 보통 | | | | |
| 낮음 | | 끔 | 끔 | 먼 거리에서는 그리지 않음 |

## 동작 줄이기
움직임을 줄이는 설정일 때: <멈춘 한 장면이나 약한 대체. 피드백 자체는 남긴다>

## 구현 사양
<glTF로 가지 않는 표현. 아래 6절>

## 예산
| 파티클 | 겹치는 반투명 층 | 텍스처 | 드로 콜 | 동시 최대일 때 합계 |
```

## 6. 웹 구현 사양에 적는 것

코드를 쓰지 않는다. 구현하는 사람이 다시 묻지 않을 만큼 적는다.

| 표현 | 적을 것 |
| --- | --- |
| 파티클 방출 | 방출 수와 간격, 수명, 처음 속도와 방향 범위, 중력, 크기 곡선, 색 곡선, 섞는 방식, 무작위의 씨앗을 고정할 수 있는지 |
| 플립북 | 한 장의 칸 수(N×M), 재생 fps, 한 번 재생인지 반복인지. 재생할 칸은 `floor(시간 × fps)`를 칸 수로 나눈 나머지다 |
| 녹아 사라짐 | 노이즈 텍스처, 문턱 값이 0에서 1로 가는 시간과 커브, 가장자리의 색과 폭 |
| 가장자리 빛 | 색, 세기, 가장자리의 날카로움(거듭제곱 값) |
| UV 흐름 | 텍스처, 방향과 속도. 두 겹이면 서로 다른 속도와 방향 |
| 빛 번짐 | 어느 재질만 번지는지, 이미시브 세기 |

- 조정 값은 모두 이름과 범위를 붙인다. 본문에 뜻 모를 숫자를 남기지 않는다.
- 모바일에서 안 되는 표현은 대체안을 함께 적거나 "데스크톱 전용"이라고 표시한다.
- 무한히 도는 효과는 탭이 숨으면 멈춘다고 명세에 적는다.
- 다른 사용자의 효과는 네트워크를 거쳐 조금 늦게 온다. 순서가 중요한 큐(둘이 손을 맞대는 순간)는 어느 쪽 시계를 기준으로 재생할지 명세에 적는다.

## 7. 동기 점검

- 큐마다 앞 2프레임, 큐 프레임, 뒤 2프레임을 렌더해 변화가 큐 프레임에 보이는지 본다.
- 소리가 붙은 큐의 90% 이상이 ±2프레임(60 fps 기준) 안에 들어와야 한다.
- 근처 100 ms 안에 사건이 없는 효과나 소리는 원인 없는 것으로 본다.
- 겹침, 여러 대상, 빠른 반복, 일시 정지와 재개, 가장 낮은 품질 단계, 동작 줄이기, 터치 화면 크기에서 어떻게 되는지 명세에 적혀 있는지 본다.
