# 지식재산 점검표

> 읽는 시점: `law-review` 4단계에서 저작물, 이름과 표지, 초상을 검토할 때.

**출발점이다. 정본이 아니다.** 법의 이름과 쟁점은 길잡이로 적었다. 조문 번호와 문장은 검토할 때 원문(국가법령정보센터)에서 확인해 리포트와 기준 문서에 확인일과 함께 적는다. 이 문서에 조문 번호가 없는 것은 일부러 비운 것이다.

검토의 결과는 "된다", "안 된다"가 아니다. 쟁점, 근거, 확실한 정도다.

## 1. 권리자의 것을 쓸 때 (Riot의 캐릭터, 이름, 그림, 소리)

이 서비스가 남의 저작물을 쓸 수 있는 근거는 둘 중 하나다. 권리자가 허락했거나(Riot의 정책), 법이 허락 없이도 쓰게 하는 경우다. 순서대로 본다.

| 볼 것 | 방법 |
| --- | --- |
| 권리자의 정책이 허락하는 범위 안인가 | `riot-policy-reviewer`의 리포트를 받는다. 직접 판정하지 않는다 |
| 정책의 범위 밖이거나 정책이 답하지 않는 쓰임이 있는가 | 그 쓰임을 목록으로 만든다. 여기부터가 법의 쟁점이다 |
| 원작을 바탕으로 새로 만든 것(닮게 만든 캐릭터 모델, 바꾼 그림)이 있는가 | 2차적 저작물의 문제다. 만들 권리는 원작자에게 있다(저작권법). 근거가 정책의 허락뿐이면 그렇게 적는다 |
| 원작을 그대로 가져온 것(뽑아낸 모델, 음원, 영상)이 있는가 | 복제와 전송의 문제다. 가장 위험이 큰 쓰임이다 |
| 저작권 표시를 지우거나 바꾼 것이 있는가 | 자산 출처 표와 원본을 대조한다 |

허락 없는 이용을 법이 받아 주는 일반 조항(공정한 이용)은 아래 네 가지를 함께 본다. **이 판단은 사람이 한다.** 검토자는 네 칸을 사실로 채워 `## 판단 필요`에 올린다.

| 요소 | 채울 사실 |
| --- | --- |
| 이용의 목적과 성격 | 수익이 있는가, 원작과 다른 새 쓰임인가 |
| 저작물의 종류와 용도 | 무엇을 가져왔는가 |
| 이용한 부분의 양과 중요성 | 전체 가운데 얼마를, 핵심인 부분을 가져왔는가 |
| 원작의 시장과 가치에 미치는 영향 | 원작을 대신하게 되는가 |

## 2. 남이 만든 자산, 음악, 글꼴

자산마다 한 줄을 채운다. **빈칸이 발견이다.**

| 이용 조건 | 공개해 쓰기 | 지켜야 할 것 |
| --- | --- | --- |
| 조건 없음(CC0, 권리 만료) | 된다 | 없다. 그래도 출처를 적는다 |
| 저작자 표시(CC-BY) | 된다 | 만든 이가 요구한 방식으로 표시 |
| 저작자 표시와 같은 조건(CC-BY-SA) | 조심해서 된다 | 표시하고, 고친 것도 같은 조건으로 |
| 비영리(NC가 붙은 것) | 수익이 있으면 안 된다 | 수익이 있는지는 기준 문서의 사실에서 본다 |
| "개인용 무료", 조건 표기 없음 | 안 되는 것으로 본다 | 만든 이에게 묻거나 바꾼다 |
| 돈을 주고 산 것 | 그 조건의 글대로 | 원본 파일의 재배포는 보통 안 된다 |

- [ ] 자산 표에 무엇, 파일, 출처(이름, 만든 이, 주소), 이용 조건, 확인 상태가 있다. 빈 출처가 없다.
- [ ] 자산마다 조건이 다른 곳에서 받은 것은 자산의 쪽마다 조건을 확인했다. 모음 전체의 조건으로 뭉뚱그리지 않았다.
- [ ] 표시가 필요한 것은 크레딧(파일이나 화면)에 무엇, 만든 이, 주소, 이용 조건이 한 줄씩 있다.
- [ ] 글꼴의 이용 조건이 웹에 싣는 것을 허락한다.
- [ ] 음악과 효과음의 출처가 있다. 권리자의 원본 음원이면 1절로 간다.
- [ ] 기억으로 적은 출처는 "확인 안 됨"으로 표시돼 있다.

## 3. 생성 도구로 만든 것 (모델, 그림, 소리)

- [ ] 무엇으로, 언제, 어떤 입력으로 만들었는지 기록이 있다.
- [ ] 도구의 약관이 이 쓰임(공개, 수익이 있으면 수익)을 허락하는지 확인한 날짜가 있다. 약관은 바뀌고 요금제에 따라 다르다.
- [ ] 입력에 남의 저작물(권리자의 그림, 선수의 사진)을 넣었는가. 넣었으면 1절과 5절의 쟁점이 따라온다.
- [ ] 입력 문장에 실제 작가, 음악가의 이름이나 저작권이 있는 가사를 쓰지 않았다.
- 사람의 창작이 들어가지 않은 생성물은 저작물로 보호받지 못할 수 있다. 서비스의 핵심 자산이 그런 것이면 `## 판단 필요`에 올린다.

## 4. 코드의 의존성

- [ ] 의존성마다 이용 조건과 지켜야 할 것(고지의 포함, 소스의 공개 같은 것)을 표로 만들었다.
- [ ] 소스 공개를 요구하는 조건의 의존성이 있는가. 있으면 어떻게 쓰이는지(묶어 배포하는가)를 적는다.
- [ ] 조건끼리 맞는지 분명하지 않으면 조심스러운 쪽으로 적고 `## 판단 필요`에 올린다.
- [ ] 저장소가 공개라면 비밀 값, 개인정보, 내부 경로가 들어 있지 않다. 보이면 `## 관찰`로 넘긴다(고치는 것은 다른 역할이다).

## 5. 이름과 표지

| 볼 것 | 방법 |
| --- | --- |
| 서비스 이름, 행사 이름, 도메인이 남의 상표나 널리 알려진 이름과 섞이는가 | 쓰이는 이름을 모두 목록으로 만든다. 게임사, 대회의 주최자, 다른 종목의 대회 이름까지 본다 |
| 공식이거나 제휴한 것으로 보일 표시가 있는가 | 로고, "공식", 대회의 이름을 그대로 쓴 곳 |
| 로고가 드러나는 곳과 그 근거 | 화면과 자산에서 로고를 모두 찾고, 근거(정책의 조항이나 허락)를 옆에 적는다 |
| "비공식", "팬 제작"의 고지 | 있는가, 눈에 띄는가. 고지는 오인을 줄이는 수단이지 면책이 아니다 |

- 상표가 충돌하는지는 이 검토에서 확정할 수 없다. 등록을 찾아보고 "없음"이 나와도 "써도 된다"가 아니다. **"충돌 위험"**으로 표시하고 사람에게 넘긴다.
- 근거가 되는 법: 상표법, 부정경쟁방지 및 영업비밀보호에 관한 법률(남의 표지와 혼동을 일으키는 쓰임, 널리 알려진 표지의 식별력을 해치는 쓰임).

## 6. 사람의 이름과 모습 (선수, 해설자, 팀)

- [ ] 실제 사람의 이름, 사진, 목소리, 닮게 만든 모습이 드러나는 곳을 모두 목록으로 만들었다.
- [ ] 그 쓰임마다 근거(본인이나 소속의 허락, 권리자 정책의 조항)가 옆에 있다. 없으면 발견이다.
- [ ] 수익과 이어지는 쓰임(광고 옆, 유료 재화)이 있는가. 있으면 위험이 커진다.
- [ ] 사실을 전하는 것(경기 결과, 기록)과 사람의 인기를 끌어다 쓰는 것을 갈라 적었다.
- 팀의 로고와 이름은 팀의 것이다. 대회를 여는 곳의 허락과 별개다.
- 근거가 되는 법: 부정경쟁방지 및 영업비밀보호에 관한 법률(널리 알려진 사람의 이름과 초상 같은 표지를 허락 없이 쓰는 것), 민법의 인격권. 조문은 원문에서 확인한다.

## 7. 남의 성과를 가져다 쓰는 것

- [ ] 남이 큰 노력으로 만든 것(대회의 중계 화면, 기록의 모음, 디자인)을 그대로 가져와 서비스의 핵심으로 쓰는가.
- 근거가 되는 법: 부정경쟁방지 및 영업비밀보호에 관한 법률(남의 상당한 투자와 노력의 성과를 허락 없이 쓰는 것). 해석의 폭이 넓은 조항이다. 해당할 수 있어 보이면 `## 판단 필요`에 올린다.

## 8. 이용자가 올리는 것

- [ ] 이용자가 올린 것(이름, 그림, 글)에 남의 저작물이 섞일 수 있는가.
- [ ] 권리를 침해당했다는 신고를 받는 길과, 받았을 때 내리는 절차가 있는가(서비스 운영 점검표의 4절과 함께 본다).
