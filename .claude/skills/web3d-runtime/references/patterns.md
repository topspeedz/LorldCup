# 3D 런타임의 구현 패턴

> 읽는 시점: `web3d-runtime` 4~7단계와 9단계. 아래는 Three.js 기준이다. React Three Fiber를 쓰기로 했으면(아키텍처 문서) 괄호 안의 대응을 쓴다.

코드 조각은 뼈대다. 설치된 버전의 API를 확인하고 쓴다.

## 1. 루프

```ts
const STEP = 1 / 60;       // 시뮬레이션 한 스텝(초)
const MAX_FRAME = 0.25;    // 숨었던 탭이 돌아올 때의 긴 프레임을 자른다
let acc = 0;

function frame(delta: number) {          // delta: 엔진의 시계가 준 초
  acc += Math.min(delta, MAX_FRAME);
  while (acc >= STEP) {
    readInput();                         // 입력 → 의도
    simulate(STEP);                      // 이동 → 충돌 → 규칙 → 생성과 소멸
    acc -= STEP;
  }
  render(acc / STEP);                    // 앞 스텝과 지금 스텝 사이를 이 비율로 보간
}
```

- 스텝 안의 순서를 고정한다: 입력 → 의도 → 이동 → 충돌 → 규칙 → 생성과 소멸 → 카메라.
- 엔진의 루프에 건다(`renderer.setAnimationLoop`. R3F는 `useFrame((_, delta) => …)`).
- 물리 라이브러리를 쓰면 그 라이브러리의 고정 스텝을 쓰고, 누산기를 하나 더 두지 않는다.
- 기다리는 시간(쿨다운)은 타이머가 아니라 시뮬레이션 시간으로 센다. 타이머는 멈춘 동안에도 흐른다.

## 2. 입력

| 장치 | 규칙 |
| --- | --- |
| 키보드 | 눌린 키의 집합을 `event.code`(물리 위치)로 관리한다. 스텝에서 집합을 읽는다. 창이 초점을 잃으면 집합을 비운다 |
| 방금 눌림 | 스텝이 끝날 때 비운다. 프레임마다 비우면 주사율이 높을 때 입력이 빠진다 |
| 터치 | 조작하는 면에 `touch-action: none`. 엄지가 닿은 자리에 생기는 이동 스틱, 화면의 다른 쪽을 끄는 것은 카메라. 닿는 대상은 44 CSS px 이상. 여러 손가락을 전제로 한다 |
| 게임패드 | 프레임마다 상태를 읽는다(이벤트가 아니다). 스틱의 데드존은 0.15~0.25, 넘는 구간은 0~1로 다시 편다 |
| 글자 입력 중 | 이벤트의 대상이 입력 칸이면 이동 키를 무시한다. 메뉴가 열리면 키 잡기를 푼다. 누가 막는지는 아키텍처 문서의 3D와 UI 사이 약속을 따른다 |

행동과 키를 잇는 표를 둔다.

```ts
const bindings = { forward: ['KeyW', 'ArrowUp'], jump: ['Space'] } as const;
// 스텝은 "forward가 눌려 있는가"만 묻는다. 어떤 키인지는 모른다.
```

## 3. 이동

- 속도를 먼저, 위치를 나중에 갱신한다: `v += a * dt`, 그다음 `p += v * dt`.
- 방향 벡터는 정규화한 뒤 속도를 곱한다.
- 감쇠는 `v *= Math.pow(damping, dt)`로 준다. 프레임마다 같은 값을 곱하면 주사율에 따라 달라진다.
- 거리 비교는 제곱 거리로 한다.
- 걷기와 달리기의 속도는 그래픽 팀 클립 표의 **기준 이동 속도**에 맞춘다. 속도를 바꾸려면 클립의 재생 속도도 같은 비율로 바꾼다. 그래야 발이 미끄러지지 않는다.
- 캐릭터는 이동 방향으로 한 번에 돌지 않고 부드럽게 돈다. 회전도 `1 - Math.exp(-k * dt)` 비율로 따라가게 한다.

## 4. 충돌과 지면

두 단계로 한다. 넓게 걸러 후보를 줄이고, 후보만 정밀하게 본다.

| 넓게 거르기 | 맞는 경우 |
| --- | --- |
| 고른 격자 | 크기가 비슷한 것이 흩어져 있다 |
| 영역을 나누는 나무 | 밀도가 고르지 않고 움직이지 않는 월드 |
| 메시의 경계 상자 나무 | 삼각형 메시에 광선을 쏠 때 |

- **지면.** 캐릭터 위에서 아래로 광선을 쏴 닿은 높이에 세운다. 광선은 충돌용 메시에만 쏜다(규약의 표기를 따른다. 보이는 메시 전체에 쏘지 않는다).
- **경사.** 닿은 면의 법선으로 기울기를 구한다. 상한을 넘으면 오르지 못하게 한다.
- **계단.** 낮은 턱은 높이 상한 안에서 올려 준다.
- **벽.** 벽 쪽 속도 성분을 뺀다: `v -= n * dot(v, n)`. 그래야 벽을 따라 미끄러진다.
- **겹침 풀기.** 가장 덜 파고든 축으로 밀어내고 그 축의 속도를 없앤다. 겹친 만큼을 한 번에 다 밀지 않고 작은 허용치를 두면 떨림이 준다.
- **빠른 것.** 한 스텝에 벽을 건너뛸 만큼 빠르면 앞 위치에서 지금 위치로 광선을 쏴 확인한다.
- 캡슐 하나와 광선으로 버티기 어려워지면(쌓기, 관절, 마찰, 회전) 물리 라이브러리가 필요한 때다. 새 의존성이므로 `ask`로 올린다.

## 5. 카메라

- 목표 자리를 정하고 그리로 감쇠하며 따라간다: `pos.lerp(target, 1 - Math.exp(-k * dt))`.
- 캐릭터에서 카메라 쪽으로 광선을 쏴 벽에 막히면 카메라를 당긴다. 벽 뒤로 파고들지 않는다.
- 코드로 움직이는 카메라와 사용자가 돌리는 카메라 조작기를 동시에 켜지 않는다. 서로 싸운다.
- 가까운 면과 먼 면의 거리를 장면에 맞게 좁힌다. 너무 넓으면 멀리 있는 면이 깜빡인다.

## 6. 불러오기, 복제, 해제

- 로더에 규약이 정한 디코더를 등록한다(Draco, Meshopt, KTX2). 디코더 파일을 어디서 받을지(자체 호스팅인지)도 규약을 따른다.
- 불러오는 동안 대체 화면을 보이고, 미리 알 수 있는 자산은 미리 받는다(R3F는 캔버스 안쪽의 `Suspense`와 `useGLTF.preload`).
- 처음 보이기 전에 셰이더를 미리 컴파일하고 텍스처를 올린다. 처음 나타날 때의 멈칫을 줄인다.
- 캐시된 장면을 여러 번 쓸 때:
  - 뼈대가 없으면 복제해서 쓴다.
  - **뼈대가 있으면 뼈대까지 복제하는 방법을 쓴다**(`three/addons`의 `SkeletonUtils.clone`. R3F는 Drei의 `<Clone>`).
  - 재질을 바꾸려면 재질도 복제하고, 복제한 재질은 내가 해제한다.
- 클립(`AnimationClip`)은 캐릭터끼리 함께 쓴다. 재생기(`AnimationMixer`)와 액션은 캐릭터마다 만든다. 뼈 이름이 같아야 한다.
- 해제:

  ```ts
  function disposeObject(root: THREE.Object3D) {
    root.traverse((o: any) => {
      o.geometry?.dispose();
      const mats = Array.isArray(o.material) ? o.material : o.material ? [o.material] : [];
      for (const m of mats) {
        for (const v of Object.values(m)) if ((v as any)?.isTexture) (v as any).dispose();
        m.dispose();
      }
    });
  }
  ```

  함께 쓰는 재질과 텍스처에는 쓰지 않는다. 렌더 타깃, 후처리, 조작기, 렌더러도 떠날 때 해제한다. 로더의 캐시는 따로 비워야 한다.

## 7. 애니메이션 상태

- 상태 기계의 전이는 함수 하나에서만 일어난다. 들어갈 때 다음 클립을 켜고, 나올 때 앞 클립을 끈다.
- 클립 사이는 0.2~0.4초로 섞어 전환한다. 걷기와 달리기처럼 발이 맞아야 하는 클립은 같은 재생 위치에서 섞는다.
- 클립은 이름으로 찾는다. 이름은 규약의 고정 문자열이다. 찾지 못하면 조용히 넘어가지 않고 오류로 드러낸다.
- 화면 밖이거나 숨은 캐릭터의 재생기는 갱신을 건너뛴다. 멀리 있는 캐릭터는 갱신 간격을 늘린다.
- **큐 발행.** Three.js에는 클립 안의 이벤트가 없다. 프레임마다 액션의 앞 시간과 지금 시간을 비교해, 그 사이에 큐의 시각이 있으면 이벤트를 낸다. 반복 재생에서 시간이 되감기면 끝까지의 구간과 처음부터의 구간을 나눠 본다. 이 함수는 렌더 없이 테스트한다.

## 8. Next.js와 함께

> 지금 앱은 정적 Three.js 앱(`web/`)이라 이 절은 쓰지 않는다. Next.js로 옮기기로 사용자가 정한 뒤에만 본다(`AGENTS.md`의 기술 스택).

- 3D의 입구 컴포넌트는 클라이언트 컴포넌트이고, 서버 렌더에서 뺀다(`next/dynamic`의 `ssr: false`). 서버 컴포넌트에서 `three`를 가져오지 않는다.
- 3D 코드는 3D가 있는 화면에서만 내려받게 한다. 캔버스가 들어갈 자리(크기 예약, 먼저 보일 그림)는 `metaverse-web-developer`가 만든다.
- 캔버스의 부모에 높이가 있어야 한다. 높이가 0이면 빈 화면이다.
- 화면 크기가 바뀌면 카메라의 가로세로 비와 투영 행렬을 갱신한다.
- 개발 모드에서는 컴포넌트가 두 번 붙는다. 붙을 때 한 일을 떼어질 때 전부 되돌리지 않으면 루프와 리스너가 둘이 된다.
- 그래픽 컨텍스트를 잃으면 캔버스를 다시 만드는 것이 단순하다. 저장소의 상태는 남는다.

## 9. 모바일

- [ ] 픽셀 비율은 기기 값과 상한(모바일 1.5) 가운데 작은 쪽
- [ ] 계단 지움을 끄거나 가벼운 것 하나만
- [ ] 단순한 재질. 투과 없음
- [ ] 그림자를 드리우는 조명 0~1개, 또는 구운 그림자
- [ ] 후처리 최소
- [ ] 품질 단계는 문턱에 여유를 두고 바꾼다
- [ ] 탭이 숨으면 루프를 멈춘다
- [ ] 조작하는 면에 `touch-action: none`, 페이지가 끌려 움직이지 않게
- [ ] 실기기에서 확인(못 했으면 리포트의 `## 남은 것`에 적는다)

## 10. 색과 빛

- 색 텍스처의 색 공간과 렌더러의 출력 색 공간을 맞춘다. glTF 로더가 정한 것을 손으로 뒤집지 않는다.
- 톤 매핑과 노출은 아키텍처 문서가 정한 값을 이름 있는 상수로 쓴다. 숫자 상수로 쓰지 않는다.
- 그래픽 팀의 조명 메모(방향, 색온도, 상대 세기, 분위기)를 런타임 조명으로 옮긴다. 금속 재질은 환경 맵이 있어야 금속으로 보인다.
- glTF 표준 재질로 안 되는 표현은 그래픽 팀의 셰이더 요청과 이펙트의 구현 사양대로 만든다. 조정 값은 이름 붙은 값으로 내놓고, 모바일 대체안을 함께 만든다.
