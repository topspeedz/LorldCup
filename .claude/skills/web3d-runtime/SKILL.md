# web3d-runtime

3D 월드의 코드는 세 가지를 가른다. 시뮬레이션(이동, 충돌, 규칙)과 렌더를 가른다. 프레임 루프와 React의 렌더를 가른다. 자산이 주는 것과 코드가 정하는 것을 가른다.

구현 Task는 완료 기준을 재현하는 테스트를 먼저 쓰고 실패를 확인한 뒤 구현한다. 검증 명령은 `AGENTS.md`의 `명령` 절에 있는 것을 쓴다. 그 절이 비어 있으면 spec의 완료 기준이 정한 명령을 쓰고, 그것도 없으면 `ask`로 받는다.

## 절차

1. **입력.** spec, 아키텍처 문서 `docs/live/web-metaverse-develop/architecture.md`, 자산 연동 규약 `asset-contract.md`, 그래픽 팀 리포트의 `## 넘기는 것`과 `## 클립` 표, 이펙트의 `spec.md`와 `cues.json`. 설치된 버전을 `package.json`에서 확인한다. 기억 속의 API로 쓰지 않는다.
2. **자산 검수.** 코드가 쓸 GLB를 세고 규약과 대조한다.

   ```sh
   node .claude/skills/blender-pipeline/scripts/glb-inspect.mjs public/assets/<종류>/<이름>.glb --names
   ```

   노드, 재질, 클립 이름과 단위가 규약과 어긋나면 자산을 고치지 않는다. 코드로 덮어 맞추지도 않는다. `ask`로 올리거나 리포트에 적는다. 자산은 그래픽 팀의 것이다.
3. **순수 로직 먼저.** 이동 계산, 입력을 행동으로 바꾸는 표, 애니메이션 상태 기계, 큐 발행, 원격 캐릭터 보간을 렌더 없이 도는 함수로 쓴다. 테스트를 먼저 쓴다.
   - 가짜 시계로 초당 30, 60, 144장을 흉내 내 같은 입력을 넣고 N초 뒤의 위치가 같은지 본다.
   - 프레임 간격 5초를 넣어도 스텝 수가 상한에서 멈추는지 본다.
   - 상태 기계는 전이표를 그대로 테스트한다.
4. **장면의 뼈대.** 캔버스는 클라이언트에서만 만든다(서버 렌더에서 뺀다). 픽셀 비율 상한, 불러오는 동안의 대체 화면, 상태 저장소를 놓는다. 장면은 작은 조각(조명, 환경, 캐릭터, 이펙트)으로 나눈다.
5. **캐릭터.** 불러오기 → 복제 → 클립 재생기 → 상태 기계가 클립을 섞어 전환 → 고정 스텝으로 움직이고 사이를 보간해 그림 → 카메라가 따라감. [references/patterns.md](references/patterns.md).
6. **충돌.** 넓게 걸러 낸 뒤 정밀하게 본다. 지면은 아래로 쏘는 광선으로, 벽은 미끄러지게 처리한다. 상자와 구 몇 개를 넘는 물리는 물리 라이브러리의 일이고, 라이브러리 도입은 새 의존성이다.
7. **이펙트와 효과음.** 이펙트 담당의 `spec.md`와 `cues.json`대로 재생한다. 클립의 재생 시간이 큐를 지나는 순간을 프레임마다 검사해 이벤트를 낸다(앞 프레임의 시간과 지금 시간을 비교하고, 반복 재생의 되감김을 처리한다). 효과는 놀이를 막지 않는다. 효과가 실패해도 이동과 규칙은 계속 돈다.
8. **여러 사용자.** [references/multiplayer.md](references/multiplayer.md). 통신 방식과 서버는 아키텍처 문서가 정한다. 정해지지 않은 것을 구현으로 정하지 않는다.
9. **시작과 끝.** 시작은 의존하는 순서로, 끝은 그 반대로 한다. 화면을 떠날 때 입력 리스너를 떼고, 루프를 멈추고, 직접 만든 그래픽 자원을 해제한다.
10. **자체 점검.** 아래 표.

## 지킬 것

| 규칙 | 이유 |
| --- | --- |
| 이동, 충돌, 규칙은 고정 스텝(1/60초)으로 돌린다. 프레임 간격은 0.1~0.25초에서 자른다 | 가변 스텝이면 점프 높이가 주사율에 따라 달라지고, 숨었던 탭이 돌아올 때 수천 스텝이 한꺼번에 돈다 |
| 그릴 때는 앞 스텝과 지금 스텝 사이를 보간한다. 순간 이동할 때는 앞 값을 지금 값으로 맞춘다 | 주사율이 높은 화면에서 끊겨 보이지 않는다. 보간한 값을 시뮬레이션에 되먹이지 않는다 |
| 프레임 루프 안에서 React 상태를 바꾸지 않는다. 참조를 직접 고친다 | 초당 60번 넘게 다시 그린다. 3D가 느려지는 가장 흔한 원인이다 |
| 프레임 루프 안에서 객체를 새로 만들지 않는다 | 쓰레기 수거가 끊김을 만든다. 모듈 수준의 임시 객체와 풀을 쓴다 |
| 입력은 장치 이벤트가 입력 객체 하나에 쓰고, 스텝이 그 객체를 읽는다 | 이벤트는 한 프레임에 여러 번 오거나 오지 않는다 |
| 행동과 키를 잇는 표를 한 층 둔다 | 터치와 게임패드를 더할 때 표만 바꾼다 |
| 상태 전이는 한 곳에서만 일어나고, 들어갈 때와 나올 때의 처리가 반드시 돈다 | 클립과 이펙트의 시작과 정리가 빠지지 않는다 |
| 캐시된 GLB 장면은 함께 쓰는 것이다. 두 번 놓거나 재질을 바꿀 때는 복제한다. 뼈대가 있는 모델은 뼈대까지 복제하는 방법을 쓴다 | 한 객체는 부모가 하나다. 그냥 복제하면 사본의 뼈가 원본을 가리킨다 |
| 장면에서 빼는 것만으로는 아무것도 해제되지 않는다. 직접 만든 지오메트리, 재질, 텍스처는 직접 해제한다. 함께 쓰는 자원은 건드리지 않는다 | 그래픽 메모리가 샌다 |
| 무거운 것은 떼었다 붙이지 않고 숨겼다 보인다 | 다시 붙이면 셰이더를 다시 컴파일하고 버퍼를 다시 올린다 |
| 렌더러를 화면마다 새로 만들지 않는다 | 브라우저의 그래픽 컨텍스트 수에는 한도가 있다 |
| 품질을 자동으로 내리고 올릴 때는 문턱에 여유(히스테리시스)를 둔다 | 문턱 하나로 켜고 끄면 품질이 떨린다 |
| 탭이 숨으면 루프를 멈춘다 | 발열과 배터리 |

## 자체 점검

| 확인 | 방법 |
| --- | --- |
| 테스트를 먼저 썼다 | 실패한 출력과 통과한 출력이 리포트에 있다 |
| 타입과 린트, 테스트 | `AGENTS.md`의 `명령` 절(또는 spec)의 명령이 통과 |
| 빌드 | 서버 렌더 단계에서 브라우저 전용 객체를 건드려 실패하지 않는다 |
| 콘솔 | 오류 0 |
| 예산 | 드로 콜과 삼각형 수를 리포트에 숫자로 적는다 |
| 누수 | 장면을 세 번 드나든 뒤 자원 수가 늘지 않는다 |
| 중복 | 화면을 세 번 다시 들어온 뒤 키 한 번에 행동 한 번 |
| 숨김 | 탭을 30초 숨겼다 돌아와도 순간 이동이나 소리 폭주가 없다 |
| 모바일 | 픽셀 비율 상한이 적용되고, 터치로 조작된다 |

실측(프레임 시간)은 이 역할이 판정하지 않는다. `graphic-performance-verifier`가 잰다. 측정용 통로가 아키텍처 문서에 정해져 있으면 그대로 내준다.

## 흔한 실수

| 실수 | 결과 |
| --- | --- |
| 키 이벤트에서 바로 이동 | 주사율에 따라 속도가 달라지고 입력이 빠진다 |
| 창이 초점을 잃을 때 눌린 키를 비우지 않음 | 돌아오면 캐릭터가 계속 달린다 |
| 대각선 이동을 정규화하지 않음 | 대각선이 41% 빠르다 |
| 같은 GLB 장면을 두 곳에 놓음 | 먼저 놓은 것이 사라진다 |
| 화면을 다시 들어올 때 루프가 둘 | 모든 것이 두 배로 빠르다 |
| 자산의 이름이 규약과 달라 코드에서 이름을 바꿔 맞춤 | 다음 자산에서 다시 깨진다. 규약의 문제로 올린다 |
| 걷는 속도를 클립과 따로 정함 | 발이 미끄러진다. 클립 표의 기준 이동 속도에 맞춘다 |
| 톤 매핑과 색 공간을 숫자 상수로 씀 | 버전에 따라 뜻이 바뀐다. 이름 있는 상수를 쓴다 |
| 내 컴퓨터에서만 여러 사용자를 시험 | 실제 지연에서 캐릭터가 튄다 |

## 완료 기준에 쓸 수 있는 검사

- 순수 로직의 테스트가 통과한다: 상태 전이표, 이동 계산, 주사율 세 가지에서 같은 위치, 스텝 수 상한.
- 타입 검사와 빌드가 통과한다.
- `glb-inspect.mjs --names`의 이름과 코드가 찾는 이름이 같다(규약 문서와 대조).
- 리포트에 드로 콜, 삼각형, 자원 수가 숫자로 있다.
