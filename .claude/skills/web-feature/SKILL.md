# web-feature

수락 기준이 일의 범위다. 기준을 재현하는 테스트를 먼저 쓰고, 그 테스트가 요구하는 만큼만 만든다. 그리고 화면 요소는 3D의 프레임을 건드리지 않는다.

검증 명령은 `AGENTS.md`의 `명령` 절에 있는 것을 쓴다. 그 절이 비어 있으면 spec의 완료 기준이 정한 명령을 쓰고, 그것도 없으면 `ask`로 받는다. 프로젝트에 없는 명령을 지어내지 않는다.

## 절차

1. **읽기.** 백로그 항목의 수락 기준을 그대로 읽는다. 아키텍처 문서 `docs/live/web-metaverse-develop/architecture.md`의 모듈 경계, 상태의 소유, 3D와 UI 사이의 약속을 읽는다. 건드릴 파일과 그것을 부르는 곳을 읽는다. `package.json`에서 설치된 버전을 확인한다. 기억 속의 API로 쓰지 않는다.
2. **만들기 전 점검.** 아래를 정하고 리포트의 `## 한 일` 첫머리에 적는다.

   | 정할 것 | 기준 |
   | --- | --- |
   | 상태를 둘 곳 | 한 컴포넌트 안 → 부모로 올림 → 드물게 바뀌는 전역은 컨텍스트 → 자주 바뀌고 여러 곳이 보는 것은 저장소 → 서버의 데이터는 서버에서 받거나 전용 도구로 → 주소에 남아야 하는 것은 주소로 |
   | 서버와 클라이언트의 경계 | 서버 컴포넌트가 기본. 클라이언트 표시는 상호작용이 필요한 끝단에만 |
   | 로딩, 빈 상태, 오류의 모양 | 셋 다 만든다 |
   | 3D와 주고받는 값 | 저장소의 어느 키와 행동을 쓰는가. 공용 약속 파일에 있는 것만 쓴다 |
   | 다시 쓸 수 있는 기존 컴포넌트 | 있으면 쓴다 |

3. **실패하는 테스트.** 수락 기준 하나에 테스트 하나를 쓰고, 기대한 이유로 실패하는지 본다. 층은 아래 표에서 고른다.
4. **통과시키기.** 테스트가 요구하는 만큼만 구현한다.
5. **다듬기.** 다듬은 뒤 전체 테스트를 다시 돌린다.
6. **검증 명령.** 타입 검사, 린트, 테스트.
7. **눈으로.** 폰 폭과 데스크톱 폭, 키보드만으로 이동, 로딩·빈 상태·오류를 억지로 만들어 확인한다. 3D가 있는 화면은 [references/canvas-ui-contract.md](references/canvas-ui-contract.md)의 점검을 한다.
8. **리포트.** 바꾼 것, 테스트 파일, 돌린 명령과 출력, 하지 않고 남긴 것.

## 무엇을 어느 층에서 시험하나

| 대상 | 층 |
| --- | --- |
| 순수 함수, 검증 스키마, 저장소의 행동 | 단위 테스트(렌더 없이) |
| 훅, 화면 조각, 로직이 있는 폼 | 컴포넌트 테스트. 네트워크는 가짜로 |
| 여러 화면에 걸친 흐름(들어가기 → 입장 → 채팅) | 브라우저 끝에서 끝까지 |
| 캔버스 안의 3D | 이 역할의 범위 밖. 캔버스가 있는지, 먼저 보일 그림이 뜨는지, 위에 뜨는 요소가 있는지만 본다 |

- 화면 요소는 사용자가 보는 것(역할과 이름)으로 찾는다. 구현 세부나 시험 전용 표식으로 찾지 않는다.
- 고정 시간 기다리기를 쓰지 않는다. 화면의 상태가 바뀌기를 기다린다.
- 가짜가 불렸는지를 단언하지 않는다. 사용자가 보는 결과를 단언한다.
- 화면 통째로 찍어 비교하는 테스트를 쓰지 않는다.

## 지킬 것

| 규칙 | 이유 |
| --- | --- |
| 과제에 필요한 줄만 바꾼다. 세 번 반복되기 전에는 추상화하지 않는다 | 리뷰할 것이 줄고 되돌리기 쉽다 |
| 밖에서 들어오는 것(네트워크, 저장된 값, 폼, 주소)은 모르는 타입으로 받아 스키마로 검증한 뒤 쓴다. 타입은 스키마에서 뽑는다 | 손으로 쓴 타입과 스키마는 어긋난다 |
| 클라이언트의 검증은 사용자를 돕는 것이다. 서버에서 다시 검증한다 | 클라이언트는 믿을 수 없다 |
| 서버 액션과 API 경로는 누구나 부를 수 있다. 검증과 권한 확인을 그 안에서 매번 한다 | 중간 단계의 확인만 믿으면 뚫린다 |
| 서버가 사용자 레코드를 통째로 화면에 넘기지 않는다. 필요한 칸만 고른다 | 비밀 값이 샌다 |
| 비밀 값을 브라우저로 가는 환경 변수에 넣지 않는다 | 누구나 본다 |
| 저장소는 필요한 값만 골라 읽는다. 통째로 읽거나, 고를 때마다 새 객체를 만들지 않는다 | 끝없이 다시 그리거나 무한 반복에 빠진다 |
| 다른 값에서 계산되는 것은 저장하지 않는다 | 두 값이 어긋난다 |
| 이펙트는 밖과 맞추는 데만 쓴다. 계산, 초기화, 이벤트 처리를 이펙트로 하지 않는다 | 한 번 더 그리고, 사슬이 된다 |
| 이펙트에서 시작한 구독, 타이머, 리스너, 요청은 반드시 정리한다 | 개발 모드에서 두 번 붙는다. 채팅 연결이 둘이 된다 |
| 화면마다 오류 경계를 둔다. 오류 경계는 로딩 경계의 바깥에 둔다 | 실패한 로딩이 끝없는 뼈대 화면이 된다 |
| 목록의 항목에는 변하지 않는 키를 쓴다 | 순번을 키로 쓰면 상태가 다른 줄로 옮겨 붙는다 |
| 누를 수 있는 것은 버튼이나 링크로 만든다. 입력에는 이름표를 단다 | 키보드와 보조 기술이 쓰지 못한다 |
| 새 의존성은 spec에 있을 때만 넣는다 | 없으면 사용자 결정이다. `ask`로 올린다 |

## 자체 점검

| 확인 | 방법 |
| --- | --- |
| 테스트를 먼저 썼다 | 실패한 출력과 통과한 출력이 리포트에 있다 |
| 타입, 린트, 테스트 | 명령이 통과. 린트 규칙을 꺼서 통과시키지 않았다 |
| 새 `any` 없음 | 바꾼 파일에서 검색 |
| 로딩, 빈 상태, 오류 | 느린 응답, 빈 목록, 실패를 억지로 만들어 각각 확인 |
| 키보드 | 탭으로 모든 조작 요소에 닿고, 초점이 보이고, Esc로 대화 상자가 닫히고 초점이 돌아온다 |
| 폰 폭 | 가로로 밀리지 않고, 안전 영역 밖에 조작 요소가 없다 |
| 3D 없는 화면 | 3D 코드를 내려받지 않는다 |
| 비밀 | 브라우저로 가는 환경 변수에 비밀이 없다 |

## 흔한 실수

| 실수 | 결과 |
| --- | --- |
| 배치 컴포넌트 맨 위에 클라이언트 표시 | 그 아래 전부가 클라이언트 코드가 된다 |
| 저장소에서 고를 때 새 객체를 돌려줌 | 무한 반복 |
| 정리 없는 이펙트 | 연결과 리스너가 겹친다. 개발 모드의 엄격 검사를 끄는 것은 해결이 아니다 |
| 숨긴 메뉴가 탭 초점을 받음 | 보이지 않는 곳으로 초점이 간다. 숨긴 것은 조작에서도 뺀다 |
| 데스크톱의 기기 흉내만으로 모바일 확인 끝 | 실제 폰의 주소 표시줄, 키보드, 안전 영역이 다르다 |
| "하는 김에" 고침 | 범위 밖의 변경이 리뷰를 흐린다. 리포트의 `## 남은 것`에 적는다 |
| 쓸 일이 없는 설정 값 | 지금 필요한 것만 만든다 |

## 완료 기준에 쓸 수 있는 검사

- 타입 검사, 린트, 테스트 명령이 통과한다(명령은 `AGENTS.md`나 spec의 것).
- 수락 기준마다 테스트가 있고, 구현 전에 실패했다는 출력이 리포트에 있다.
- 바꾼 화면의 오류 경계 파일이 있다.
- 3D가 없는 화면의 네트워크 요청에 3D 코드가 없다.
