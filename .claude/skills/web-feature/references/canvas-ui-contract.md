# 3D 캔버스와 화면 요소가 함께 있을 때

> 읽는 시점: 3D가 있는 화면을 만들거나 고칠 때. 캔버스가 들어갈 자리, 캔버스 위에 뜨는 요소, 3D와 주고받는 상태, 모바일과 접근성.

캔버스 안은 `metaverse-3d-developer`의 것이다. 이 역할은 캔버스가 들어갈 자리와 그 위에 뜨는 것, 둘 사이의 약속을 맡는다. 약속의 정본은 아키텍처 문서와 공용 약속 파일이다. 여기 없는 값을 주고받아야 하면 구현으로 정하지 않고 팀장에게 올린다.

## 1. 캔버스가 들어갈 자리

| 항목 | 기준 |
| --- | --- |
| 크기 예약 | 자리의 높이를 먼저 잡는다(화면 높이 단위나 가로세로 비). 캔버스가 뜰 때 다른 요소가 밀리지 않는다 |
| 먼저 보일 그림 | 캔버스가 준비되기 전에는 정지 그림을 보인다 |
| 늦게 받기 | 3D 코드는 따로 묶고, 이 자리가 있는 화면에서 첫 화면이 그려진 뒤에 받는다. 서버 렌더에서 뺀다 |
| 화면 밖이거나 탭이 숨으면 | 3D에 멈추라는 신호를 준다 |
| 다른 화면으로 갈 때 | 3D가 자원을 해제하게 한다 |
| 그래픽 컨텍스트를 잃으면 | 정지 그림으로 돌아간다 |
| 움직임을 줄이는 설정 | 정지한 한 장면을 보이고 반복되는 움직임을 멈춘다 |
| 실패 | 3D가 뜨지 못해도 화면의 제목과 주된 버튼은 쓸 수 있다 |

## 2. 캔버스 위에 뜨는 요소

- 상태 표시, 메뉴, 채팅 창, 대화 상자는 캔버스 안에 그리지 않고 **캔버스 옆의 문서 요소로** 위에 겹친다. 글자의 선명도, 글꼴, 번역, 보조 기술이 그래야 산다.
- 겹치는 층의 바탕은 포인터 이벤트를 받지 않게 하고(`pointer-events: none`), 실제 조작 요소만 받게 한다(`auto`). 그래야 빈 곳을 끌어 3D를 조작할 수 있다.
- 3D 안의 물체에 붙어 따라다녀야 하는 이름표만 캔버스 쪽에 둔다. 이것은 3D 개발자와 정한다.
- 움직이는 장면 위의 글자는 자기 바탕판 위에 놓는다. 장면의 가장 밝은 때와 가장 어두운 때 모두에서 읽혀야 한다.

## 3. 키보드와 초점

- 글자를 입력하는 동안(채팅 칸에 초점이 있을 때) 이동 키가 3D로 가면 안 된다. 어느 쪽이 막는지는 약속에 적혀 있다. 약속이 없으면 올린다.
- 메뉴나 대화 상자가 열리면 3D의 키 잡기와 포인터 잠금이 풀려야 한다. 닫히면 초점이 연 자리로 돌아간다.
- 대화 상자가 열린 동안 뒤의 요소는 탭 초점을 받지 않는다.
- 3D 조작만으로 할 수 있는 중요한 일에는 화면 요소로도 하는 길을 둔다.

## 4. 3D와 주고받는 상태

| 원칙 | 이유 |
| --- | --- |
| 프레임마다 바뀌는 값(위치, 카메라)은 3D가 갖고, 화면 요소는 그것을 프레임마다 읽지 않는다 | 화면 요소가 초당 60번 다시 그려진다 |
| 화면 요소가 봐야 하는 값은 3D가 묶어서 드물게 저장소에 쓴다(바뀔 때만, 또는 낮은 빈도로) | 같은 이유 |
| 3D의 루프는 저장소를 구독하지 않고 그때그때 읽는다 | 화면 요소가 다시 그려져도 3D의 프레임에 영향이 없다 |
| 화면 요소는 3D의 객체를 직접 만지지 않는다. 저장소의 행동만 부른다 | 경계가 한 곳이다 |
| 키와 행동의 이름은 공용 약속 파일에 있는 것만 쓴다 | 한쪽이 몰래 바꾸면 다른 쪽이 깨진다 |

## 5. 모바일 웹

| 항목 | 기준 |
| --- | --- |
| 화면 높이 | 앱의 틀은 주소 표시줄을 따라 바뀌는 높이 단위(`dvh`), 첫 화면은 가장 작을 때의 높이 단위(`svh`) |
| 안전 영역 | 화면을 가장자리까지 쓰고(`viewport-fit=cover`) 안쪽 여백으로 조작 요소를 안전 영역 안에 둔다 |
| 확대 | 사용자의 확대를 막지 않는다 |
| 입력 글자 | 16px 이상. 작으면 초점을 줄 때 화면이 확대된다 |
| 닿는 대상 | 44×44 CSS px 이상, 사이 8px |
| 누름 | 버튼에 `touch-action: manipulation`과 눌린 모양 |
| 캔버스 자리 | 페이지가 끌려 넘어가지 않게(`overscroll-behavior: none`). 끌기를 막는 것은 조작하는 면에만(`touch-action: none`) |
| 올려 둠 효과 | 올려 둘 수 있는 기기에서만(`hover: hover`와 `pointer: fine`) |
| 화면 키보드 | 키보드가 올라와도 입력 칸과 보내기 버튼이 가려지지 않는다 |

## 6. 접근성

| 항목 | 기준 |
| --- | --- |
| 글자의 대비 | 본문 4.5:1, 큰 글자 3:1, 조작 요소와 초점 표시 3:1 |
| 포인터 대상 | 최소 24×24 CSS px, 터치는 44×44 |
| 초점 | 항상 보인다. 순서가 화면의 순서와 같다 |
| 알림 | 3~5초 뒤 스스로 닫히고, 초점을 빼앗지 않고, 보조 기술에 조용히 알린다 |
| 상태 | 색만으로 알리지 않는다. 글이나 모양을 함께 쓴다 |
| 소리 | 소리로만 주는 정보가 없다. 설정에 음량과 끄기가 있다 |

## 7. 서버 기능

| 항목 | 기준 |
| --- | --- |
| 응답의 모양 | 성공과 실패의 모양을 하나로 정해 모든 경로가 쓴다 |
| 상태 코드 | 잘못된 요청 400, 로그인 필요 401, 권한 없음 403, 없음 404, 충돌 409, 검증 실패 422, 너무 잦음 429, 서버 오류 500 |
| 목록 | 한 번에 주는 수에 상한을 둔다(기본 25, 최대 100) |
| 로그인 상태 | 스크립트가 읽지 못하는 쿠키에 둔다. 브라우저 저장소에 토큰을 두지 않는다 |
| 권한 | 경로와 서버 액션 안에서 매번 확인한다 |
| 실시간(채팅, 존재) | 통신 방식과 서버는 아키텍처 문서가 정한다. 정해지지 않았으면 올린다 |

## 8. 페이지 지표

3D가 있는 화면도 지킨다.

| 지표 | 기준 | 3D 화면에서 지키는 법 |
| --- | --- | --- |
| 가장 큰 내용이 그려지기까지 | 2.5초 이하 | 먼저 보일 그림이 그 내용이 되게 한다 |
| 입력 뒤 다음 화면까지 | 200 ms 이하 | 화면 요소의 처리를 3D의 무거운 일과 한 프레임에 겹치지 않게 한다 |
| 배치 밀림 | 0.1 이하 | 캔버스 자리의 크기를 예약한다 |

## 9. 3D가 있는 화면의 점검

- [ ] 느린 네트워크에서도 제목과 주된 버튼이 첫 화면에 있다.
- [ ] 정지 그림에서 캔버스로 바뀔 때 다른 요소가 밀리지 않는다.
- [ ] 3D가 없는 화면은 3D 코드를 받지 않는다.
- [ ] 빈 곳을 끌면 3D가 조작되고, 버튼을 누르면 버튼만 눌린다.
- [ ] 채팅 칸에 글자를 치는 동안 캐릭터가 움직이지 않는다.
- [ ] 화면을 떠났다 돌아와도 연결과 리스너가 하나다.
- [ ] 움직임을 줄이는 설정에서 반복되는 움직임이 멈춘다.
