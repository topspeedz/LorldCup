# 감정표현 4종 확대·효과음 — FX1

2026-11-13 · U-사용자-5 / C-사용자-1·2 · FIX1 웹 팀 인계. 이 명세와 `cues.json.fx`는 **권장안**이며 `web/config/characters.json`이나 재생 코드를 적용한 결과가 아니다.

사용자가 알게 되는 것: 내 감정과 같은 방 관람객의 감정을 큰 실루엣과 짧은 소리로 읽고, 던진 계란과 보낸 하트가 경기장 대형 스크린에 도착했음을 확인한다. 감정 목표는 장난스러운 응원이다. 기존 네 종류·색·클립을 유지하고, 입자 수보다 폭과 퍼지는 거리로 키운다.

## 큐와 시간

`cues.json.cues`의 `sound`는 아래 효과음 이벤트 이름이며 `sounds[event].files`가 실제 파일명이다. `null`은 그 큐만 무음이라는 뜻이다. 모든 감정표현에는 소리 큐가 있다. `frame = eventFrames[clip][event][eventIndex] + offsetFrames`(단일 이벤트는 인덱스 없음), 시각은 `frame/30`이다.

`clip:null`인 명중·소멸 큐는 새 애니메이션 이벤트가 아니다. 같은 감정표현의 `after` 큐부터 `timeFormula`만큼 지난 순간이다. 공식의 키는 해당 `fx.<emote>`에서 찾고 문자열을 eval하지 않는다. 기본 프레임 숫자는 대조용이며 설정 시간이 바뀌면 다시 계산한다.

| 종류 | 예고 | 타격 | 여운·종료 |

## 하트: 손 → 스크린 → 터짐

1. **출발:** release 프레임까지 믹서를 먼저 진행해 `hand_L`, `hand_R` 월드 위치 평균 + `worldUp × handOffsetMeters`를 `S`로 저장한다. 손에서 위로 오르며 줄던 이전 release 동작은 이 비행으로 바뀐다. 카메라/플레이어 위치를 출발점으로 쓰지 않는다.
2. **목표:** 기존 `window.arena.screen.faces`의 `{name,position,normal,width,height}`만 읽는다. 발신 아바타 월드 위치 `A`에 대해 `dot(normalize(normal), normalize(A-position))`가 가장 큰 양수인 면을 고르고 동률은 배열 앞 면이다. 그 면 중심 `P`를 release 때 고정한다. 카메라가 보던 면이 아니라 발신 아바타를 향한 면이다. 준비된 양수 면이 없으면 비행·명중·그 소리를 생략하고 손 표식만 정리한다.
3. **궤적:** `u=clamp((now-releaseTime)/0.8,0,1)`, 중심은 `(1-u)S + uP + worldUp × 4 × 1.2 × u(1-u)`. 카메라를 향하는 하트 실루엣, 폭 0.65 m, 비행 중 축소·회전·추적 목표 변경 없음. 큰 dt로 끝을 넘겨도 명중 위치는 P로 정확히 고정한다.
4. **명중:** 중심 하트를 제거하고 `P+n×0.04`에서 파편 4개와 `heart_pop`을 같은 순간 시작한다. `right=normalize(worldUp×n)`, `up=n×right`. 파편 j는 `θ=2πj/4+π/4`, `v=clamp(age/0.5,0,1)`일 때 `P+n×0.04+(right cosθ+up sinθ)×R×v`. 크기는 위 수축 곡선이다. 목표 면에 평행하게 놓으며 양면으로 보이게 한다.
5. **면 경계:** 실제 파편 폭 `B=min(burstSizeMeters,width,height)`, 반경 `R=min(burstRadiusMeters,max(0,(width-B)/2),max(0,(height-B)/2))`. 가장자리 밖으로 나가지 않도록 이 값으로 제한한다. 면 전체를 덮는 판·영상 위 DOM은 없다.
6. **수명:** release 후 하트는 클립과 독립이다. 정상 클립 종료(3.6초), 새 감정표현, 앉은 화면에서 로컬 몸 숨김에도 날아간 하트·터짐을 지우지 않는다. 사람당 스크린 하트 상태는 하나(비행 1개 **또는** 터짐 4개), 새 release는 이전 상태를 소리/명중 없이 종료하고 교체한다. 방 떠남·아바타 제거·모듈 dispose에는 전부 정리한다.

## 계란: 비행·큰 터짐·작은 자국

release 순간 `Prop_Egg`의 월드 위치·회전·확대된 스케일을 보존한다. 목표 면 선택은 하트와 같은 기존 규칙이며 `P`를 고정한다. 기존 포물선 식의 `flightSeconds`만 1.2→0.8초, `arcHeightMeters`는 0.6 m 그대로다. 비행 시간이 1/3 짧아지고 동일 거리의 평균 속도는 1.5배다.

명중에서 계란을 숨기고 소리·조각·자국을 한 번 낸다. 조각 j는 `θ=2πj/count`, 면 접선 `(right cosθ+up sinθ)×2.4 m/s`, 법선 `n×0.5 m/s`, 월드 아래 중력 `3 m/s²`를 쓴다. 0.6초 선형 수축 후 제거하며, 감정표현 종류를 바꿔도 이미 생긴 조각은 사람당 한 묶음의 독립 수명이다. 면 밖 조각에는 불투명 껍데기 실루엣만 있고 지속 자국은 없다.

자국은 기존 식 `min(splatSizeMeters,sqrt(width×height×maxSplatAreaRatio),width,height)`의 정사각 경계 안에 둔다. **`splatSizeMeters=0.7`, `maxSplatAreaRatio=0.0025`(면의 0.25%), `maxSplatsPerFace=1` 모두 유지**한다. 한 면의 새 명중은 이전 자국을 교체하고 새 1.5초 수명을 시작한다. 0.9초 유지 후 0.6초간 `splatOpacity×(1-v)²`로 사라져 정확히 1.5초에 슬롯 반환. 알파 0.7·면 오프셋 0.02 m·renderOrder 2 유지. “더 큰 터짐”은 자국 상한 해제가 아니다.

## 구현 사양·Full Mode·정리

- 기존 환호·하트·화내기 공유 InstancedMesh와 네 256² RGBA CanvasTexture를 재사용한다. alphaTest 0.5, transparent false, NormalBlending, depthTest true, depthWrite false, toneMapped false. 하트 스크린 파편은 같은 텍스처·풀을 쓰되 양면 재질과 renderOrder 2로 영상 구멍(1) 뒤에 그린다. 손 하트도 깊이 검사를 유지한다.
- 계란 비행은 기존 지오메트리·재질 공유, 조각은 기존 양면 불투명 삼각형, 자국만 transparent true인 평면이다. mipmaps false, LinearFilter, sRGB 그대로다. 새로운 텍스처·셰이더·패키지를 요구하지 않는다.
- **Full Mode에는 네 종류의 손·머리 표식, 손 계란, 비행체, 파편, 자국을 모두 숨긴다.** 현재 코드의 표식 그리기에도 같은 조건을 적용해야 한다. canvas 외부 플레이어/iframe/CSS에는 추가하지 않는다. 권고: 이때 감정 SFX도 멈추고 새 큐를 소비만 한다; 영상 소리·재생 시간은 건드리지 않는다.
- 숨김 탭에서도 감정 SFX는 멈추고, 복귀 때 단조 경과 시간으로 만료된 상태를 먼저 정리한다. 과거 명중·소리를 몰아 재생하거나 만료된 자국을 되살리지 않는다.
- 내/원격 모두 같은 큐 재생기와 `emoteSeq` 중복 방지 사용. 새 네트워크 필드는 없다. 수신 후 각 화면의 클립 시각에 맞추며, 발신 시각이 없는 계약에서 화면 간 절대 동시를 약속하지 않는다. 중복·역순 seq·아바타 재생성으로 소리나 비행을 재시작하지 않는다.

- 기본 소리 켬 지시와 기존 전체 볼륨을 따른다. 첫 사용자 클릭/키 동작으로 AudioContext를 풀고 파일을 미리 디코드한다. 잠금/로딩 중 놓친 큐는 뒤늦게 재생하지 않는다. 오류 시 해당 소리만 생략하며 시각 피드백은 계속한다. 새 볼륨 UI·브라우저 저장소는 이 인계의 범위가 아니다.
- 중복 키는 참가자 + emoteSeq + 이벤트 + eventIndex. 같은 렌더에서 넘긴 음성 큐 중 **가장 최근 한 개**, 현재보다 0.1초 이상 지난 큐는 무음 처리한다. 시각 큐는 정상 처리한다. 박수 접촉마다 한 번, angry는 첫 swing만, egg는 scream과 실제 impact 각각 한 번이다.
- 변형은 `(emoteSeq + eventIndex) % 파일 수`를 출발 인덱스로 쓰고 같은 발신자·같은 sound 이벤트의 직전 파일과 같으면 다음 파일로 넘긴다. pitch/gain 무작위 변조 없이 녹음 세 테이크를 교대한다. 새 공개 클립 이벤트를 만들지 않는다.
- 한 발신자 동시 1소리. 박수는 기존 짧은 박수가 끝난 뒤 다음 접촉이 온다. 명중음은 같은 발신자의 오래된 소리를 대체한다. 팬 합계 데스크톱 16 / 모바일 14, 선수 10을 합친 기존 26 / 24 상한을 넘지 않는다. 내 행동 → 가까운 원격 → 먼 원격 순으로 남기고 넘친 오래된/먼 원격음을 생략한다. 할당/교체/음량 변경은 20 ms 램프로 끊김을 줄인다.
- 여러 명 동시 재생의 합산 음량, 방송과의 균형, 화내는 목소리의 어울림은 실제 청음으로 판정한다. 파형·디코드 검사만으로 “잘 들린다” 또는 “화가 난다”고 합격시키지 않는다.

## 품질·동작 줄이기

기존 품질별 텍스처 크기·풀 상한을 유지하며 새 품질 UI는 없다. OS reduced-motion에서는 환호 2개·화내기 2개를 중심 고정 후 수축, 손 하트 중심 1개, 스크린 하트는 호·회전 없는 0.8초 직선 비행 후 중심 한 개 0.5초 수축, 계란은 0.8초 직선 비행·조각 2개·같은 1.5초 자국으로 바꾼다. 소리 끔에서도 형태와 도착 피드백은 남는다. 작은 화면에서 얼굴을 가리면 크기만 축소하기 전에 소켓 오프셋과 가림을 QA가 확인한다.

## 예산

설계 상한이며 실측이 아니다. 다음 감정표현과 이미 놓은 계란·하트가 겹치는 경우까지 센다.

| 항목 | 최악의 경우 |
| --- | --- |
| 표식·파편 | `16 × (max(12,4,4) + 계란 조각 8 + 독립 하트 상태 4) = 384`개. 비행 하트 1개는 독립 하트 상태 4개 안에 포함 |
| 하트 인스턴스 풀 | `16 × (손 표식 4 + 스크린 상태 4) = 128`개; 기존 하트 묶음 용량만 늘림. 384 집계에 포함 |
| 계란 | 손 16 + 비행 16 = 32개, 위 384와 별도; 원본 지오메트리 공유 |
| 자국 | 네 면 × 1 = 4개, 면별 알파 층 1·경계 면적 0.25% 이하, 1.5초 |
| 텍스처 | 기존 `4 × 256 × 256 × 4 = 1,048,576`바이트 = **1 MiB**, 밉맵 없음; 2 MiB 이하 |
| 추가 드로 콜 | 표식 3 + 계란 비행 1 + 조각 1 + 자국 4 = **9**. 하트 비행·터짐은 같은 하트 배치. 기존 손 계란 최대 16을 합치면 25 |
| 반투명 | 자국만 면별 1층. 나머지는 alphaTest/불투명; 커진 실루엣의 채우기 비용은 별도 실측 필요 |
| 오디오 | 팬 16/14, 선수 포함 26/24 이하. 변형 파일 수와 동시 재생 수는 다름 |
| 목표 | 경기장 60 FPS, 장면 텍스처 500 MiB 이하. FIX1 통합 후 QA·성능 담당 판정 |

## 구현 뒤 확인할 장면

큐 앞 2프레임·큐·뒤 2프레임, 4종 각각 로컬/원격 1회, 박수·화내기 동시 이벤트 중복, 실제 계란 2.5배, 하트 양 끝과 목표 면, 클립 종료 후 남은 수명, 늦은 dt·중복 seq·종류 교체·16명 동시·네 면 명중을 확인한다. Full Mode의 **모든** 표식·SFX 제거, mute, autoplay 잠금, 숨김 탭 복귀, dispose, 작은 화면·reduced-motion도 포함한다. FX1은 브라우저·GPU·청음을 실행하지 않았다.
