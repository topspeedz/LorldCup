# 티켓 화면 명세

- 읽는 시점: 입구의 티켓 창(`web/ui/ticket.js`), 발급 카드, 닫은 뒤 다시 여는 길, 입구 3D 표시를 만들거나 고칠 때(T29 화면 적용, T33 UX 동행, T24 아트 대조)
- 역할과 소유 범위: 창·카드·다시 열기·막힘 알림의 자리, 크기, 위계, 겹침, 컴포넌트 상태의 모양과 입구 3D 표시의 색·밝기. 흐름과 문구는 UX 명세 `docs/live/product/ux/ticket.md`, 값은 `tokens.md`
- 소유 에이전트: `ui-designer`
- 마지막으로 갱신한 phase: 2026-11-13-ux-motion-rooms (T60 마우스 우선 개정)
- 입력: UX 명세 `docs/live/product/ux/ticket.md`, 토큰 `docs/live/graphicmodel/ui/tokens.md`, `web/config/ticket.json`(`promptDistance` 3 m, `cardMs` 1800)

## T60 마우스 우선 개정

- 입구까지 가는 길은 WASD 또는 바닥 클릭(UX H-D2). 다음 할 일 줄은 왼쪽 위 그대로. 티켓 창의 "들어가기" 뒤 포인터를 잠그지 않는다.
- 창을 닫은 뒤 다시 여는 버튼은 왼쪽 위 다음 할 일 줄 자리(커서 풀림 조건 없이 늘 눌린다). 390×844도 같은 자리, ☰ 없음.
- 이 절이 아래 표보다 이긴다. 아래 표의 "커서 풀림", "메뉴 버튼(☰)", "키 안내 줄", "아래 1단/2단", "조작 막대", "Esc → 메뉴" 줄은 이 절의 자리로 읽는다. 공용 자리는 `hud-controls.md`(T60), 시안은 `preview/mouse/`.

## 규칙

- 창은 오른쪽에 둔다. 입구(정면)와 내 캐릭터가 창 왼쪽으로 보인다. 자리와 너비는 팀·캐릭터 창(`team-select.md`)과 같아서 "팀 고르기"로 넘어갈 때 같은 자리에서 바뀐다.
- 주된 조작(강조색 버튼)은 언제나 하나다: 첫 미완료 단계의 버튼, 발급 뒤에는 "들어가기".
- UX 결정 1~3은 추천 채택: 새 키(T) 없음 — 다시 여는 길은 "막음에 닿으면 다시 뜸" + 입구 앞의 "티켓 창 열기" 버튼. 받은 티켓 다시 보기는 넣지 않는다. 입구 표시는 `ticket.js` 안의 간단한 Three.js 표시.
