# 좌석 화면 명세

- 읽는 시점: 3D 좌석 표시, 좌석 앞 "E 앉기"와 "앉기 (E)" 버튼, 앉은 화면의 HUD를 만들거나 고칠 때.
- 역할과 소유 범위: 좌석에 닿는 화면 요소의 자리, 크기, 위계, 겹침, 상태별 모양. 흐름은 UX 명세, 키 안내 줄과 상태 표시의 모양은 `hud-controls.md`가 정본이다.
- 소유 에이전트: `ui-designer`
- 마지막으로 갱신한 phase: 2026-11-13-ux-motion-rooms (T60 마우스 우선 개정)
- 입력: UX 명세 `docs/live/product/ux/seat.md`, 토큰 `docs/live/graphicmodel/ui/tokens.md`, 공용 자리 `docs/live/graphicmodel/ui/hud-controls.md` `## 공용 자리`

## T60 마우스 우선 개정

- "앉기" 버튼 `#seat-toggle`은 걷기 중에도 가까운 빈 좌석이 있으면 아래 가운데에 보이는 강조 버튼이다(커서 풀림 상태가 없다). 키 힌트 상자 맨 위에 "E 앉기"(지금 할 일 모양).
- 3D 빈 좌석 표시는 클릭할 수 있다(UX H-D2, 클릭 → 점프해 날아가 착지 → 앉기). 표시 위에 커서가 오면 커서 모양 `pointer`, 표시가 지금 크기의 1.2배(가까운 것과 같은 모양)로 밝아진다. 글 "빈 좌석"은 그대로. 세부 빛은 `graphic-effect-vfx-designer`.
- 앉으면: 상태 글자 "앉음"이 없다. (T67, 사용자 2026-11-14) 스크린 바로 아래 가운데에 큰 조작 막대 하나 — "F Full Mode(강조)", "E / Esc 일어나기", "Alt 감정표현", "볼륨" — 를 두고, 오른쪽 위 키 힌트 상자와 오른쪽 아래 묶음은 따로 두지 않는다(자리·크기는 `hud-controls.md` 「상태별 배치」 조작 막대 줄). Esc는 Full Mode나 감정표현 메뉴가 열려 있으면 그것만 닫고, 아니면 일어난다. 막대는 영상 위에 오지 않는다. 일어나도 포인터를 잠그지 않는다.
- 390×844: 방향 버튼은 남고, 행동 버튼은 왼쪽 아래 세로 3칸, "앉기"는 방향 버튼 위 가운데(`m-near-seat.png`, `m-seated.png`).
- 이 절이 아래 표보다 이긴다. 아래 표의 "커서 풀림", "메뉴 버튼(☰)", "키 안내 줄", "아래 1단/2단", "조작 막대", "Esc → 메뉴" 줄은 이 절의 자리로 읽는다. 공용 자리는 `hud-controls.md`(T60), 시안은 `preview/mouse/`.

## 결정 필요

- **(결함, 좌석 담당에게)** 세로 화면(390×844)에서 앉으면 카메라가 (−35.4, −2.9, −35.5)로 물러나 관중석 벽 뒤에 서고 화면이 검다(`bg/m-seated.png`, `bg/m-seated-check.png`, 확인 스크립트 `check-m-seated.mjs`). `web/seat-mode.js`의 거리 식 `max(face.width/camera.aspect, face.height)/…/screenFill`이 세로 화면에서 매우 커진다. 앉은 카메라를 고치는 Task(좌석 적용, 사용자의 "맨 뒤 좌석" 요청과 같은 묶음)가 세로 화면 거리 상한이나 벽 앞 멈춤을 정해야 한다. 이 명세의 모바일 앉기 배치는 영상이 가운데 띠에 보인다는 가정이다.
- 3D 좌석 표시의 색: 지금 `0x7aefdc`(청록)과 가까운 하나 `0xffdf77`(노랑)은 아트 디렉션 팔레트에 없다. 코디네이터 메모(추천이 없으면 아트 디렉션 색 안에서)대로 빈 좌석 `color-accent`, 가까운 하나 `color-text` + 1.2배 + 키캡 "E"로 정했다. 세계 안 표시의 밝기 위계는 `graphic-effect-vfx-designer`가 확인하고, 다르게 정하면 그 값이 이긴다.
- 키 안내 "E·WASD 일어나기": UX 요구(UX-S-R05)는 "E·WASD", 문자열 표는 "E 일어나기"다. 키캡 `E` `WASD` + "일어나기"로 둘 다 맞췄다.
