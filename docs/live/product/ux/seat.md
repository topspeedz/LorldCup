# 좌석 UX 명세

- 읽는 시점: 좌석 찾기, 앉기, 앉은 화면, 일어나기를 만들거나 고칠 때. UI 화면 명세(`docs/live/graphicmodel/ui/seat.md`), 감정표현·좌석 적용 Task, HUD·Full Mode 적용 Task, UX 동행이 읽는다.
- 역할과 소유 범위: 3D 안의 좌석 표시, 앉기·일어나기의 흐름, 앉은 상태에서 보이고 눌리는 것. 앉은 상태의 Full Mode는 `full-mode.md`, 감정표현은 `emote-menu.md`, 키 안내 줄과 상태 표시는 `hud-controls.md`가 정본이다.
- 소유 에이전트: `ux-designer`
- 마지막으로 갱신한 phase: 2026-11-13-ux-motion-rooms (T59 마우스 우선 개정)


## T59 마우스 우선 개정 (이 문서의 앞선 줄보다 우선)

- 사용자 원문: "일단 모든것은 키보드가 기본이 아니고 Mouse로 UI를 설정할 수 있는 형태가 될 수 있을 정도로 초반 UI에서 직관적으로 알 수 있게 해줘" / "커서풀림 이런것도 다 없애" / "esc키에 따라 UI나오는것도 없애줘". 조작 모델은 `hud-controls.md` 2.1(H-D1 잠그지 않음, H-D2 바닥·좌석 클릭)이 정본이다.
- 상태가 줄어든다: '커서 풀림'·메뉴 상태가 없다. 걷기에서도 커서가 보이고 버튼이 늘 같은 자리에 보인다. Esc는 화면 요소를 열거나 숨기지 않는다(창·메뉴·Full Mode를 닫는 것만 예외). 상태 글자(걷는 중·앉음·커서 풀림)와 ☰ 메뉴 버튼은 없다.
- 아래 표에서 '걷기(포인터 잠금)', '커서 풀림'은 '걷기(커서 보임)' 한 줄로 읽는다.

## 2. 사용자 흐름

```text
[걷기] → [좌석 줄이 보임: 빈 좌석 위에 "빈 좌석" 표시]
   → [다가감: 가장 가까운 하나가 밝고 커짐 + "E 앉기"(표시 곁이나 키 안내 줄)]
   → E (커서 풀림·터치면 "앉기" 버튼)
   → [앉음: 카메라가 스크린을 향함, 커서가 보임, 상태 "앉음",
          버튼 "Full Mode"·"감정표현"·"일어나기", 조작 막대, 키 안내 "E 일어나기 · F Full Mode · Alt 감정표현"]
        ├─ Full Mode 버튼·F → [Full Mode] → 닫기(Esc·F·닫기 버튼) → [앉음으로 돌아옴] (full-mode.md)
        ├─ 감정표현 버튼·Alt → [메뉴] → 고름 → [앉은 그대로 + 반응] (emote-menu.md)
        └─ 일어나기 버튼·E·WASD → [앉기 전 자리에 서 있음 → 걷기(포인터 다시 잠김)]
```

- 반응: E를 누른 그 프레임에 앉는다(카메라 전환이 반응이다). 일어나기도 같다.
- 일어난 뒤 걷기로 돌아가려면 포인터를 다시 잠가야 한다. 버튼·E·W는 사용자 조작(클릭·키)이라 그 자리에서 잠글 수 있다. 잠금이 실패하면(터치 등) 커서 풀림 상태로 서 있고 `#fallback` 안내 대신 터치 화면의 보통 화면이 된다.
- 첫 방문: 앉는 법을 따로 가르치지 않는다. 좌석 표시가 눈을 끌고, 가까이 가면 키가 뜬다.

## 4. 수락 기준 제안

- 숨은 조작 없음: 앉은 직후 아무 키도 누르지 않은 첫 그림에 Full Mode 버튼, F 안내, 일어나기 버튼, 감정표현 버튼이 보이고 마우스로 눌린다(BL-0030 (3), BL-0031 (3)).
- 좌석 앞 걷기 그림에 "E 앉기"가 보인다.
- 일어나기는 버튼, E, WASD 어느 것으로도 되고, 앉기 전 자리로 돌아온다.
- 터치에서 앉아도 "마우스 잠금을 사용할 수 없습니다"가 뜨지 않는다.
