# 티켓 UX 명세

- 읽는 시점: 입구의 티켓 창(`web/ui/ticket.js`)과 입구 막음, 티켓 발급 연출을 만들거나 고칠 때. UI 명세 `docs/live/graphicmodel/ui/ticket.md`와 화면 적용, UX 동행이 5절을 쓴다
- 역할과 소유 범위: 입구에서 티켓을 받아 안으로 들어가기까지의 흐름, 상태별 조작, 문구. 팀 고르기 창은 [팀·캐릭터 선택](team-select.md), 감정표현 메뉴는 `emote-menu.md`, 모양은 UI 명세가 소유한다
- 소유 에이전트: ux-designer
- 마지막으로 갱신한 phase: 2026-11-13-ux-motion-rooms (T59 마우스 우선 개정)


## T59 마우스 우선 개정 (이 문서의 앞선 줄보다 우선)

- 사용자 원문: "일단 모든것은 키보드가 기본이 아니고 Mouse로 UI를 설정할 수 있는 형태가 될 수 있을 정도로 초반 UI에서 직관적으로 알 수 있게 해줘" / "커서풀림 이런것도 다 없애" / "esc키에 따라 UI나오는것도 없애줘". 조작 모델은 `hud-controls.md` 2.1(H-D1 잠그지 않음, H-D2 바닥·좌석 클릭)이 정본이다.
- 상태가 줄어든다: '커서 풀림'·메뉴 상태가 없다. 걷기에서도 커서가 보이고 버튼이 늘 같은 자리에 보인다. Esc는 화면 요소를 열거나 숨기지 않는다(창·메뉴·Full Mode를 닫는 것만 예외). 상태 글자(걷는 중·앉음·커서 풀림)와 ☰ 메뉴 버튼은 없다.
- 아래 표에서 '걷기(포인터 잠금)', '커서 풀림'은 '걷기(커서 보임)' 한 줄로 읽는다.
- 이 문서에서: 막힌 이동 안내(이동 버튼 `#quick`)는 버튼이 없어지므로 뜻이 없다. 마우스만으로 입구에 가는 길은 H-D2(바닥 클릭)다.

## 지금 앱에서 읽은 것 (설계 근거)

- 입구(`ticket.json` `barrier`)에 보이지 않는 막음이 있다. 막음에서 3 m(`promptDistance`) 안에 오면 티켓 창이 뜨고 포인터 잠금이 풀린다.
- 창은 두 단계다: "응원할 팀 고르기"(버튼 "팀 고르기" → 팀·캐릭터 창), "응원하기 한 번"(버튼 "응원하기" → 감정표현 메뉴). 감정표현 아무것이나 한 번이면 된다.
- 두 단계가 끝나면 팀 색 티켓 카드가 돌며 나타나고(1.8초, `cardMs`) 막음이 풀린다. 그 뒤 창은 숨는다. 입구가 열렸다는 글이나 다시 걷는 안내는 없고, 잠금이 풀린 채라 사용자가 스스로 다시 잠가야 한다.
- 닫기 "✕"로 닫으면 3 m 밖으로 나갔다 올 때까지 다시 뜨지 않는다.
- 티켓 전에는 이동 버튼의 로비·무대 앞이 막히는데 반응이 없다(`entry-loading.md` UX-E09).
- 멀리서는 티켓이 필요하다는 것을 알 길이 없다(입장 패널의 설명은 "입구를 향해 걸어가세요"뿐).

## 2. 사용자 흐름

```text
[걷기: 다음 할 일 "입구로 가서 티켓 받기"] → [입구에 다가감: 3D 입구 표시(닫힘)]
   → [3 m 안: 티켓 창 뜸, 포인터 풀림, 커서 보임, 초점은 첫 미완료 단계 버튼]
   → [팀 고르기 → 팀·캐릭터 창(team-select.md) → 팀 고름 → 닫기 → 티켓 창: 팀 단계 체크]
   → [감정표현 → 감정표현 메뉴(emote-menu.md) → 하나 고름 → 티켓 창: 감정표현 단계 체크]
   → [카드 나옴(1.8초) → "입구가 열렸습니다" + "들어가기" 버튼(초점), 3D 입구 표시 열림, 다음 할 일 줄 사라짐]
   → [들어가기·Enter·캔버스 클릭] → [포인터 잠김, 걷기] → [입구 통과]
```

### 되돌아가는 길

```text
[티켓 창] → [닫기(✕)·Esc] → [창 닫힘, 입구 앞에 "티켓 창 열기" 버튼(커서 보임)] → [버튼] → [티켓 창]
                                                                          → [캔버스 클릭] → [걷기, HUD에 "입구 앞에서 T 티켓"]
[티켓 창이 닫힌 채 막음에 닿음] → [티켓 창 다시 뜸]
[입구에서 3 m 밖으로 걸어 나감] → [창이 숨음, 진행한 단계는 남는다]
```

- 무엇이 알려 주는가: 3D 입구 표시(닫힘·열림), 창의 두 단계 체크, 카드, "입구가 열렸습니다", 다음 할 일 줄.
- 진행한 단계는 창을 닫거나 멀어져도 남는다(지금 동작 유지).

## 3. 상태별 조작 명세

| 상태 | 무엇이 보이는가 | 무엇으로 조작하는가(마우스, 키, 터치) | 다른 상태에서 이 조작을 찾는 길 | 커서와 포인터 잠금 |
| --- | --- | --- | --- | --- |
| 첫 방문(설명 없음) | 걷기 HUD의 다음 할 일 "입구로 가서 티켓 받기", 입구의 3D 표시 | 걸어서 다가감 | 다음 할 일 줄과 입구 표시 | 걷기와 같음 |
| 로딩 중·실패 | 보이지 않는다 | 없음 | 로딩 뒤 다음 할 일 줄 | 커버가 덮음 |
| 걷기(커서 보임) | 3 m 밖: 다음 할 일 줄. 3 m 안: 티켓 창 | WASD나 입구 쪽 바닥 클릭(`hud-controls.md` H-D2)으로 다가가면 창이 저절로 뜬다. 창을 닫은 뒤에는 입구 앞 "티켓 창 열기" 버튼 | 다음 할 일 줄, 입구 표시 | 커서 보임 |
| 앉기 | 티켓 창은 뜨지 않는다(좌석은 입구 안에만 있다) | 없음 | 해당 없음 | 해당 없음 |
| Full Mode | 티켓 창은 뜨지 않는다 | 없음 | Full Mode를 닫은 뒤 입구로 | `full-mode.md` |
| 작은 창·모바일(터치) | 창은 화면 폭에 맞고 방향 버튼 위로 뜬다. 창을 닫으면 입구 앞에 "티켓 창 열기" 버튼 | 터치로 버튼, 방향 버튼으로 걷기 | 입구 앞의 "티켓 창 열기" 버튼 | 잠금 없음 |
| 창 열림 | 제목, 두 단계(각 버튼), 끝난 단계의 체크, 닫기 | 클릭·Tab·Enter·터치, Esc·닫기로 닫음 | — | 커서 보임 |
| 발급 뒤 | 카드, "입구가 열렸습니다", "들어가기" 버튼 | 들어가기 클릭·Enter·터치 | — | 커서 보임(잠그지 않음) |

- 숨은 조작 점검: 닫은 창을 다시 여는 길(UX-K06)은 키(T)를 HUD에 적거나, 키를 더하지 않는 대안으로 "막음에 닿으면 다시 뜸"과 메뉴 상태의 "티켓 창 열기" 버튼(입구 앞, 티켓 전만)을 둔다. `## 결정 필요` 1.
- 입력 대안: 단계 버튼은 마우스·키보드·터치. 감정표현은 버튼(메뉴를 엶) 또는 Alt.

## 4. 수락 기준 제안

- 숨은 조작 없음: 처음 온 사람이 설명 없이 티켓을 받는 곳과 방법, 닫은 창을 다시 여는 길을 찾는다. 5절의 모든 줄이 그림 한 장이나 조작 한 번으로 맞는다.
- 티켓을 받으면 "입구가 열렸습니다"가 보이고 조작 한 번으로 다시 걷는다.
- 티켓 없이 막음에 닿으면 이유가 보인다.
