# 감정표현 메뉴 UX 명세

- 읽는 시점: 감정표현 메뉴(박수 환호·하트·화내기·계란 던지기)를 열고 고르는 화면이나, 감정표현 이펙트의 사용자 반응을 만들거나 고칠 때. UI 화면 명세(`docs/live/graphicmodel/ui/emote-menu.md`), 감정표현·좌석 적용 Task, UX 동행, 이펙트 연출 명세(`art/vfx/emotes/spec.md`)가 읽는다.
- 역할과 소유 범위: 메뉴를 여는 길, 고르기, 닫기, 고른 뒤 사용자가 보는 반응. 이펙트의 모양과 큐 프레임은 연출 명세와 큐 표(`art/vfx/emotes/cues.json`)가 정본이고, 계란이 스크린에 맞는 동작은 설계서 5.6이 정본이다. HUD에서 이 메뉴를 찾는 길은 `hud-controls.md`.
- 소유 에이전트: `ux-designer`
- 마지막으로 갱신한 phase: 2026-11-13-ux-motion-rooms (T59 마우스 우선 개정)


## T59 마우스 우선 개정 (이 문서의 앞선 줄보다 우선)

- 사용자 원문: "일단 모든것은 키보드가 기본이 아니고 Mouse로 UI를 설정할 수 있는 형태가 될 수 있을 정도로 초반 UI에서 직관적으로 알 수 있게 해줘" / "커서풀림 이런것도 다 없애" / "esc키에 따라 UI나오는것도 없애줘". 조작 모델은 `hud-controls.md` 2.1(H-D1 잠그지 않음, H-D2 바닥·좌석 클릭)이 정본이다.
- 상태가 줄어든다: '커서 풀림'·메뉴 상태가 없다. 걷기에서도 커서가 보이고 버튼이 늘 같은 자리에 보인다. Esc는 화면 요소를 열거나 숨기지 않는다(창·메뉴·Full Mode를 닫는 것만 예외). 상태 글자(걷는 중·앉음·커서 풀림)와 ☰ 메뉴 버튼은 없다.
- 아래 표에서 '걷기(포인터 잠금)', '커서 풀림'은 '걷기(커서 보임)' 한 줄로 읽는다.

## 2. 사용자 흐름

```text
[걷기] ─Alt─→ [메뉴 열림: 커서 풀림, 첫 버튼에 초점, 제목 "감정표현", 닫는 길 "Alt·Esc 닫기"]
   ├─ 버튼 클릭 / Enter → [메뉴 닫힘 → 다시 걷기] → [아바타 동작 + 큐 순간의 이펙트] → [동작 끝 → 서 있기]
   ├─ Alt → [닫힘 → 다시 걷기]
   └─ Esc → [닫힘 → 커서 풀림(걷기로 돌아가지 않는다)]

[커서 풀림·터치] ─"감정표현" 버튼─→ [메뉴 열림] → 고르면 [닫힘 → 같은 상태] → [동작 + 이펙트]
[앉기] ─Alt 또는 "감정표현" 버튼─→ [메뉴 열림] → 고르면 [닫힘 → 앉은 그대로] → [앉은 시야에 이펙트 또는 "○○를 보냈어요" 알림]
[티켓 "응원하기"] → [메뉴 열림] → 고르면 티켓 단계가 끝난다(`ticket.md`)
[Full Mode] → Alt는 아무것도 하지 않는다. 감정표현은 Full Mode를 닫은 뒤에
```

- 반응: 버튼은 누르는 순간 눌림 모양. 고른 뒤 메뉴가 닫히는 것과 동작의 시작이 같은 프레임 근처(출발값: 0.2초 안). 이펙트는 큐 표의 순간.
- 계란 던지기: 놓는 순간 계란이 손에서 출발해 던진 사람을 가장 바로 보는 스크린 면에 맞고, 자국은 1.5초 안에 사라진다(설계서 5.6, 결정 14). 영상은 끊기지 않는다.
- 끊기는 규칙: 걷기·뛰기·점프로 끊긴다. 사용자에게 따로 알리지 않는다(움직임이 곧 반응이다).

## 4. 수락 기준 제안

- 숨은 조작 없음: 걷기·커서 풀림·앉기·터치의 그림 한 장마다 메뉴를 여는 길(Alt 안내나 버튼)이 보인다. Full Mode에서는 메뉴가 열리지 않는다.
- 고른 감정표현은 큐 순간의 이펙트로 재생되고, 같은 방 다른 사람 화면에서도 보인다(BL-0028 (1)(2)).
- 앉아서 골라도 내 화면에 반응이 보인다.
- 마우스 없이 네 감정표현을 모두 고를 수 있다.
