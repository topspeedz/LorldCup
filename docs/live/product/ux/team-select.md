# 팀·캐릭터 선택 UX 명세

- 읽는 시점: 팀·캐릭터 선택 창(`web/ui/team-select.js`)과 여는 버튼을 만들거나 고칠 때. UI 명세 `docs/live/graphicmodel/ui/team-select.md`와 화면 적용, UX 동행이 5절을 쓴다
- 역할과 소유 범위: 응원팀과 캐릭터를 고르는 흐름, 상태별 조작, 문구. 티켓 조건으로서의 팀 고르기는 [티켓](ticket.md)이, 모양은 UI 명세가 소유한다
- 소유 에이전트: ux-designer
- 마지막으로 갱신한 phase: 2026-11-13-ux-motion-rooms (T59 마우스 우선 개정)


## T59 마우스 우선 개정 (이 문서의 앞선 줄보다 우선)

- 사용자 원문: "일단 모든것은 키보드가 기본이 아니고 Mouse로 UI를 설정할 수 있는 형태가 될 수 있을 정도로 초반 UI에서 직관적으로 알 수 있게 해줘" / "커서풀림 이런것도 다 없애" / "esc키에 따라 UI나오는것도 없애줘". 조작 모델은 `hud-controls.md` 2.1(H-D1 잠그지 않음, H-D2 바닥·좌석 클릭)이 정본이다.
- 상태가 줄어든다: '커서 풀림'·메뉴 상태가 없다. 걷기에서도 커서가 보이고 버튼이 늘 같은 자리에 보인다. Esc는 화면 요소를 열거나 숨기지 않는다(창·메뉴·Full Mode를 닫는 것만 예외). 상태 글자(걷는 중·앉음·커서 풀림)와 ☰ 메뉴 버튼은 없다.
- 아래 표에서 '걷기(포인터 잠금)', '커서 풀림'은 '걷기(커서 보임)' 한 줄로 읽는다.

## 지금 앱에서 읽은 것 (설계 근거)

- 여는 버튼 `#team-select-open`("팀·캐릭터")은 걷는 동안 숨는다(`body.walking`). 티켓 창의 "팀 고르기" 버튼도 같은 창을 연다(`TEAM_SELECT_OPEN`).
- 창은 화면 가운데의 대화 상자다. 응원팀 두 개(GEN.G, BLG)와 캐릭터 목록(`characters.json`)이 버튼이고, 누르는 즉시 적용된다(확인 버튼 없음). 고른 것은 테두리와 배경색(`aria-pressed`)으로만 다르다.
- 팀은 처음에 비어 있고(`team=null`), 캐릭터는 기본값(`fan_f1`)이 골라져 있다.
- 닫기는 "✕"(접근성 이름 "닫기")와 Esc. 닫으면 초점이 여는 버튼으로 간다. 창 밖 클릭으로는 닫히지 않는다.
- 창이 화면 가운데를 덮어 바뀐 내 캐릭터(3인칭 카메라 가운데)를 가린다.

## 2. 사용자 흐름

```text
[커서 풀림(Esc 뒤, 메뉴 요소 보임)] → [팀·캐릭터 버튼] → [창: 응원팀 줄(초점은 지금 고른 것, 없으면 첫 팀), 캐릭터 줄, 닫기]
   → [팀 버튼] → [버튼에 체크, 내 캐릭터 팀 색 바뀜] → [캐릭터 버튼] → [내 캐릭터 모습 바뀜]
   → [닫기(버튼·Esc·창 밖)] → [메뉴로, 초점은 팀·캐릭터 버튼]

[티켓 창] → [팀 고르기] → [같은 창] → [팀 버튼] → [닫기] → [티켓 창으로, 팀 단계에 체크(ticket.md)]
```

- 무엇이 알려 주는가: 고른 버튼의 체크 표시와 강조, 창 옆으로 보이는 내 캐릭터의 바뀐 모습, 응원팀 줄의 "아직 고르지 않음".
- 고르기는 되돌릴 수 있다. 다른 버튼을 누르면 바뀐다. 확인 단계를 두지 않는다(지금 동작 유지).
- 티켓을 받은 뒤에도 팀을 바꿀 수 있다. 받은 티켓은 그대로다(지금 동작 유지).

## 3. 상태별 조작 명세

| 상태 | 무엇이 보이는가 | 무엇으로 조작하는가(마우스, 키, 터치) | 다른 상태에서 이 조작을 찾는 길 | 커서와 포인터 잠금 |
| --- | --- | --- | --- | --- |
| 첫 방문(설명 없음) | 입장 전 메뉴에 "팀·캐릭터" 버튼. 창을 열면 응원팀 줄은 "아직 고르지 않음" | 클릭·Tab+Enter·터치 | 입장 전 화면에 보인다. 티켓 창의 "팀 고르기"로도 연다 | 커서 보임 |
| 로딩 중·실패 | 보이지 않는다(커버 아래) | 없음 | 로딩이 끝나면 메뉴에 보인다 | 커버가 덮음 |
| 걷기(커서 보임) | 오른쪽 아래 "팀·캐릭터" 버튼(늘 보임) | 클릭(기본), Tab·Enter | 늘 같은 자리 | 커서 보임, 잠그지 않음(`hud-controls.md` H-D1) |
| 앉기 | 걷기와 같은 버튼 | 클릭 | 늘 같은 자리 | 커서 보임 |
| Full Mode | 보이지 않는다 | 없음. Full Mode를 닫으면 같은 자리에 보인다 | Full Mode 닫기 | `full-mode.md` |
| 작은 창·모바일(터치) | "팀·캐릭터" 버튼(늘 보임, ☰ 없음). 창은 화면 폭에 맞고 세로로 스크롤 | 터치, 창 안 세로 스크롤, 닫기 버튼 | 늘 보인다 | 잠금 없음 |
| 창 열림 | 창, 내 캐릭터(가려지지 않음), 닫기 | 버튼 클릭·Tab·Enter·Space·터치. Esc·닫기·창 밖 클릭으로 닫음 | — | 커서 보임. Tab은 창 안에서만 돈다 |

- 숨은 조작 점검: 여는 버튼은 어느 상태에서도 숨지 않는다(Full Mode 말고). 키를 눌러야 나타나는 길이 없다.
- 창이 열린 채 걷기로 가지 않는다. 창이 열려 있으면 캔버스 클릭은 창을 닫기만 한다.

## 4. 수락 기준 제안

- 숨은 조작 없음: 처음 온 사람이 설명 없이 모든 상태에서 이 창을 찾는다. 5절의 모든 줄이 그림 한 장이나 조작 한 번으로 맞는다.
- 창이 열린 채로 내 캐릭터의 바뀐 모습이 보인다.
- 고른 것이 색 말고 체크나 글자로도 보인다.

## 결정 필요

1. **창 위치(UX-T02).** 추천: 넓은 화면에서는 창을 화면 한쪽(왼쪽 아래나 오른쪽)으로 옮겨 가운데의 내 캐릭터가 보이게 한다. 미리보기 3D를 따로 그리지 않는다(비용 없음, 새 렌더 없음). 위치와 크기는 UI 명세가 정한다.
2. **창 밖 클릭으로 닫기(UX-T10).** 추천: 넣는다. 캔버스 클릭이 걷기로 들어가는 동작과 겹치므로, 창이 열려 있으면 그 클릭은 창만 닫는다.
