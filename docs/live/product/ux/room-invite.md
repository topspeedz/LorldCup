# 방 초대 UX 명세

- 읽는 시점: 오른쪽 설정 묶음의 '같이 보기' 버튼, 방 상태 한 줄, 자동 연결 고지, 초대 링크로 온 사람의 흐름을 만들거나 고칠 때. UI 명세 `docs/live/graphicmodel/ui/room-invite.md`, 아키텍처의 고정 ID 표(T61), 화면 적용(T46b), UX 재걷기가 5절을 쓴다
- 역할과 소유 범위: 입장 뒤 같은 경기를 보는 사람들과 방으로 묶이는 흐름이 사용자에게 어떻게 보이고 무엇으로 조작되는가. 방 키 찾기·넘기기의 규칙은 설계서 5.4와 아키텍처가, 운영자 화면(`web/ops.html`)은 이 명세 밖이다. 고지의 뜻은 법무(T07 원문, 쉬운 말 확인 T62)가 소유한다
- 소유 에이전트: ux-designer
- 마지막으로 갱신한 phase: 2026-11-13-ux-motion-rooms (T59 마우스 우선 개정, T59b 법무 고지 반영, T59c 초대 링크의 상영 시각)

## 이번 개정의 근거 (T59)

- 사용자가 8780에서 직접 써 본 원문(`_workspace/qa/2026-11-13-ux-motion-rooms/spec/user-feedback.md`): "링크는 복사가 됐는데 여기화면에 방번호에 넣어야되는줄알았어 그만큼 UX가 헷갈리고 조잡해" / "혼자 시청중 표시 띄워놓고. 같이 보기 버튼 하나만 넣어" / "아 그래 그러면 Default가 아무랑 보기라서 입장이 될거고 / 같이 보기 버튼하나만있어도되겠네" / "혼자시청중도 없애야지 default가 항상 방에 들어가있는거니까." / "이런 설명도 일반사용자가 어떻게 알아, 전문 용어 넣어봐야 의미도 없고" / "오른쪽에 일단 설정관련된건 다 몰아, 볼륨조절도 넣을수있게 해주고"
- 마우스 걷기(T59, 리포트 `_workspace/product/2026-11-13-ux-motion-rooms/00c_ux-designer_mouse-first_v1.md`): 방 패널은 걷는 동안 숨고, 걷기에서 메뉴로 돌아오는 길이 Esc뿐이라 마우스만 쓰는 사람은 '초대 링크 복사'에 닿지 못했다. 패널 안에는 박스 7개(제목, 고지 둘, 복사, 방 번호 입력, 옮기기, 나가기)가 있었다.
- 그대로인 것: 입장 뒤 자동 배치(BL-0032 (1), 결정 10, 빈 방이 없으면 새 방의 방장), 순번 방 키, 방장 넘기기, 혼자 남아도 영상이 끊기지 않음(BL-0032 (5)), 정원 16, 이벤트 `room:state`·`room:joined`·`room:left`(공용 약속).
- 없애는 것: 방 번호 입력, '이 방으로 옮기기', '방 나가기'·'다시 같이 보기', '혼자 시청 중' 글자, 패널 안 두 번째 고지, '함께 둘러보기' 패널 자체. 방 키는 방송별로 나뉜다(BL-0035, 첫 페이지는 `entry-loading.md`).

## 2. 사용자 흐름

### 자동 배치 (처음 온 사람)

```text
[첫 페이지: 방송 카드 + 고지 한 줄과 "자세히" + 들어가기] → (클릭) [로딩] → [경기장, 소리 켜짐]
   → 자동으로 방에 듦(화면 표시 없음)
      ├ 다른 사람이 있음 → [오른쪽 묶음 "N명 같이 보는 중", 다른 캐릭터가 보임]
      ├ 빈 번호 → 새 방의 방장(표시 없음)
      ├ 모든 방 가득 / 연결 실패 → 혼자 봄(표시 없음, 영상 그대로)
```

- 찾는 동안에도 걷고 영상을 본다. 방에 드는 순간 영상은 그 방의 회차로 한 번 맞춰진다(설계 5.4).

### 같이 보기 (친구 부르기)

```text
[오른쪽 묶음의 '같이 보기'] → (클릭) [링크 복사 → 버튼 아래 "복사됐어요. 친구에게 보내면 같은 방으로 들어와요"(6초 뒤 사라짐)]
   ├ 휴대폰에 공유 창이 있음 → [공유 창] → 닫으면 위와 같은 한 줄
   ├ 복사 실패 → ["이 링크를 친구에게 보내세요" + 링크 글(눌러 전체 선택)]
   └ 연결 안 됨 → [링크 복사 + "지금은 같이 보기에 연결되지 않아요. 잠시 뒤 다시 눌러 주세요"]
[친구: 링크 열기] → [로딩(첫 페이지 건너뜀)] → ["친구가 부른 방으로 들어가요" + 들어가기] → (클릭)
   ├ 자리 있음 → [같은 방, 양쪽에 "2명 같이 보는 중"]
   └ 가득 참 → ["친구 방이 가득 차서 다른 방으로 들어왔어요"(3초) → 자동 배치]
   그리고 영상 (UX-M15):
   ├ 링크의 상영 시각이 아직 → [상영 대기: 왼쪽 위 "N분 뒤 시작해요"(entry-loading.md)] → [시작 시각에 처음부터 재생]
   ├ 이미 시작 → [대기 없이 그 방의 위치로 맞춰 재생]
   └ 시각 없음(생방송) → [바로 재생]
```

- 나가는 길: 안내 한 줄은 저절로 사라진다. 누를 것이 더 없다.
- 방을 옮기거나 나가는 조작은 없다. 혼자 보고 싶으면 그냥 본다(혼자일 때 표시 없음).

### 방장 넘기기와 혼자 남기

```text
[2명 이상] → (방장이 나감) → [화면 변화 없음, 영상 그대로] → [사람 수만 바뀜]
[2명] → (상대가 나감) → [사람 수 줄이 사라짐, 영상 그대로]
[혼자] → (누가 들어옴) → ["1명이 들어왔어요"(3초), "2명 같이 보는 중"]
```

## 3. 상태별 조작 명세

| 상태 | 무엇이 보이는가 | 무엇으로 조작하는가(마우스, 키, 터치) | 다른 상태에서 이 조작을 찾는 길 | 커서와 포인터 잠금 |
| --- | --- | --- | --- | --- |
| 첫 페이지(설명 없음) | 들어가기 버튼 바로 위 고지 한 줄과 "자세히" | 들어가기 클릭(`entry-loading.md`) | — | 커서 보임 |
| 초대 링크로 옴 | 로딩 뒤 "친구가 부른 방으로 들어가요" + 들어가기 | 들어가기 클릭 | — | 커서 보임 |
| 로딩 중·실패 | 없음. 로딩 실패면 연결을 시작하지 않는다 | 없음 | — | 커버가 덮음 |
| 걷기 | 오른쪽 묶음: '같이 보기' 버튼, 2명 이상이면 "N명 같이 보는 중" | 클릭. Tab·Enter | 늘 같은 자리에 보인다(숨지 않음) | 커서 보임(`hud-controls.md` H-D1: 입장이 포인터를 잠그지 않음) |
| 앉기 | 걷기와 같다 | 클릭 | 늘 보인다 | 커서 보임 |
| Full Mode | 숨는다(영상만). 사람이 들고 나도 Full Mode를 깨지 않는다 | 없음. Full Mode를 닫으면 다시 보인다 | Full Mode 닫기 → 같은 자리 | `full-mode.md` |
| 작은 창·모바일(터치) | 오른쪽 위 묶음 안 '같이 보기'(아이콘 + 글) | 터치. 공유 창이 있으면 공유 창 | 늘 보인다 | 잠금 없음 |

- 숨은 조작 없음: '같이 보기'는 Full Mode 말고 어느 상태에서도 숨지 않는다. 키를 눌러야 나타나는 패널이 없다.
- 입력 대안: 마우스 클릭(기본), Tab·Enter, 터치(공유 창). 복사가 안 되면 링크 글.
- 색: 사람 수 줄과 결과 줄은 정보 색이다. 오류 색을 쓰는 방 글은 없다.

## 4. 수락 기준 제안

- 마우스만으로: 처음 온 사람이 걷기와 앉기 상태에서 키를 쓰지 않고 '같이 보기'를 눌러 링크를 복사하고, 그 링크를 연 두 번째 사람이 같은 방에 든다. 5절의 모든 줄이 그림 한 장이나 클릭 한 번으로 맞는다.
- 화면 어디에도 방 번호·코드 입력칸, '혼자 시청 중', 방 번호 글자가 없다.
- 고지 한 줄에 전문 용어가 없고 뜻은 그대로다(T62 판정 원문에서 "접속 주소" 뒤 괄호의 IP 표기만 뺌). "자세히"는 첫 페이지와 초대 들어가기 화면 둘 다에 있고 그 첫 글에 "IP 주소"가 있다.

## 결정 필요

1. **사람 수 줄을 남길지.** 추천: 2명 이상일 때만 "N명 같이 보는 중" 한 줄. 사용자는 '혼자 시청 중'을 없애라고 했고 사람 수는 말하지 않았다. 같이 보는 사람이 있다는 것을 알려 주는 유일한 글이다. 대안: 이것도 없앤다(캐릭터가 보이는 것으로 충분). 비용은 같다.
2. **고지 "자세히" 접기.** 정함(T62 승인): 첫 페이지와 초대 들어가기 화면 둘 다에 두고, 안의 글은 6절의 세 글 그대로다.
3. **방장 넘기기 때 새 방장 알림("이제 내가 방장입니다").** 추천: 없앤다. 방장만의 조작이 없고, 사용자는 방 상태 글을 줄이라고 했다.
