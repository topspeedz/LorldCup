# Full Mode UX 명세

- 읽는 시점: 스크린 영상을 크게 보는 Full Mode의 들어가기·보기·나오기를 만들거나 고칠 때. UI 화면 명세(`docs/live/graphicmodel/ui/full-mode.md`), HUD·Full Mode 적용 Task, UX 동행이 읽는다.
- 역할과 소유 범위: Full Mode를 찾는 길(모든 상태), 들어간 화면에서 할 수 있는 것, 나오는 길과 돌아가는 상태. 영상 재생·편성·음량 규칙은 설계서 5.5와 `web/screen-video.js`의 몫이고, 조작 막대의 음량·소리·연결 안내는 `hud-controls.md`가 정본이다.
- 소유 에이전트: `ux-designer`
- 마지막으로 갱신한 phase: 2026-11-13-ux-motion-rooms (T59 마우스 우선 개정)


## T59 마우스 우선 개정 (이 문서의 앞선 줄보다 우선)

- 사용자 원문: "일단 모든것은 키보드가 기본이 아니고 Mouse로 UI를 설정할 수 있는 형태가 될 수 있을 정도로 초반 UI에서 직관적으로 알 수 있게 해줘" / "커서풀림 이런것도 다 없애" / "esc키에 따라 UI나오는것도 없애줘". 조작 모델은 `hud-controls.md` 2.1(H-D1 잠그지 않음, H-D2 바닥·좌석 클릭)이 정본이다.
- 상태가 줄어든다: '커서 풀림'·메뉴 상태가 없다. 걷기에서도 커서가 보이고 버튼이 늘 같은 자리에 보인다. Esc는 화면 요소를 열거나 숨기지 않는다(창·메뉴·Full Mode를 닫는 것만 예외). 상태 글자(걷는 중·앉음·커서 풀림)와 ☰ 메뉴 버튼은 없다.
- 아래 표에서 '걷기(포인터 잠금)', '커서 풀림'은 '걷기(커서 보임)' 한 줄로 읽는다.

## 2. 사용자 흐름

```text
[걷기] ─F(키 안내 줄 "F Full Mode")─→ [Full Mode]
[커서 풀림] ─"Full Mode (F)" 버튼 또는 F─→ [Full Mode]
[앉기] ─"Full Mode (F)" 버튼(앉은 직후부터 보임) 또는 F─→ [Full Mode]
[터치] ─"Full Mode" 버튼─→ [Full Mode]

[Full Mode: 영상 16:9 가득, 아래 막대(소리, 음량, "지금: 재방", 연결 안내), "Full Mode 닫기 (Esc)" 버튼에 초점, 상태 "Full Mode"]
   ├─ "Full Mode 닫기" 버튼 / Esc / F / 브라우저 전체 화면 풀기 → [들어오기 전 상태로]
   └─ 영상 안을 누름 → 초점이 플레이어로 → 닫기 버튼은 그대로 보임(키가 먹히지 않을 때의 길)
```

- 반응: 버튼이나 F를 누른 그 프레임에 창 가득 화면이 된다. 브라우저 전체 화면은 그 뒤에 따라온다(거절돼도 창 가득은 남는다).
- 브라우저 전체 화면 중 첫 Esc는 브라우저가 먼저 받아 전체 화면을 푼다. 이것도 Full Mode 닫기로 본다(지금 `fullscreenchange` 처리, 한 번의 Esc로 나온다).
- 첫 방문: Full Mode를 가르치는 안내는 따로 두지 않는다. 키 안내 줄과 버튼 이름이 길이다.

## 4. 수락 기준 제안

- 숨은 조작 없음: 걷기·커서 풀림·앉기·터치 각각의 그림 한 장에 Full Mode 버튼이나 "F Full Mode" 안내가 보인다. 특히 앉은 직후 아무 키도 누르지 않은 그림에 버튼이 보이고 클릭 한 번으로 들어간다(BL-0030 (3), BL-0031 (3)).
- Full Mode에서 닫기 버튼이 늘 보이고, 영상 안을 누른 뒤에도 보인다.
- 나오면 들어오기 전 상태로 돌아가고 영상은 끊기지 않는다.
